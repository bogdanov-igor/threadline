# Как работать с файлом

Порядок всегда один: открыть, поправить, посмотреть проверку, прочитать отчёт, применить.

![Путь файла: открыть, поправить, проверка, отчёт, применить. Если проект изменили, текст остаётся на месте](diagram:file-flow)

## Шаг 1. Откройте текст

Откройте страницу «Файл проекта». Вы увидите весь проект в YAML с номерами строк. Скрытые записи тоже есть в тексте. Такой текст, собранный из базы, называется выгрузкой.

Переключатель YAML и JSON меняет формат. Правки при этом сохраняются. Если в YAML есть комментарии, страница предупредит, что в JSON они пропадут.

Кнопка «Скачать» сохраняет текст с экрана файлом `acme-project.yaml`. Кнопка «Схема формата» открывает описание всех полей для редактора кода.

![Страница «Файл проекта»: текст с номерами строк, переключатель формата, кнопки «Скачать» и «Загрузить файл»](shot:file-page)

## Шаг 2. Поправьте текст

Есть два способа.

- **Прямо на странице.** Щёлкните в текст и печатайте. Tab вставляет пробелы, Esc и затем Tab выводит из текста.
- **В своём редакторе.** Скачайте файл, поправьте, затем нажмите «Загрузить файл» или перетащите файл на текст. Подойдёт `.yaml`, `.yml` или `.json` в кодировке UTF-8, до 2 МБ.

Загруженный файл только попадает в редактор. Проект от этого не меняется. Если в тексте уже есть ваши правки, страница спросит, заменить ли их.

Черновиков нет: текст живёт только на этой странице. При уходе браузер спросит подтверждение.

## Шаг 3. Смотрите проверку

Проверка идёт сама, в два этапа.

1. **Синтаксис.** Сразу после ввода. Ошибка отмечена у строки: «Ошибка синтаксиса: строка 14, столбец 7». Такой текст дальше не проверяется.
2. **Содержание.** На паузе в наборе. Рядом с текстом сначала «Ждём паузу, чтобы проверить», затем «Проверяем…», затем «Проверено».

Ошибка содержания состоит из пути и сообщения:

```text
systems.1.methods.3.name — не длиннее 80 символов
```

Путь читается так: вторая система, четвёртый метод, поле `name`. Счёт идёт с нуля. Щелчок по пути ведёт к нужной строке.

Показаны сразу все ошибки, а не только первая. Что значит каждое сообщение, описано на странице «Сообщения проверки».

![Ошибка проверки: строка отмечена в тексте, справа путь и сообщение, кнопки применения нет](shot:file-page-error)

## Шаг 4. Прочитайте отчёт

Отчёт говорит, что случится, если применить текст. Значений в нём нет, только названия записей и полей.

![Отчёт проверки: группа «Будет изменено» с названием записи и поля, кнопка «Применить 1 изменение»](shot:file-page-report)

| Группа | Что значит | Что сделать |
|---|---|---|
| «Будет добавлено» | Такой записи ещё нет | Сверьте с документом |
| «Будет изменено» | Запись есть, поля другие. В строке названы поля | Проверьте каждую строку: не стирает ли файл нужное |
| «Будет скрыто» | У записи появилось `hidden: true` | Только то, что скрываете намеренно |
| «Будет возвращено» | Скрытая запись снова без `hidden: true` | Проверьте, что возвращаете намеренно |
| «Ручные правки пропущены» | Запись правили формой, файл её не тронет | Оставьте или включите «Заменить ручные правки» |
| «Удалённые записи файл не возвращает» | Запись удалили формой | Оставьте или включите «Заменить ручные правки» |
| «без изменений: N» | Запись совпала с файлом | Ничего |
| «нет в файле: N» | Запись из прошлого файла есть в проекте, но её нет в тексте. Она останется. Записи, созданные формой, сюда не входят | Ничего, если вы не хотели её скрыть |

Если применять нечего, страница так и скажет. Кнопки применения в этом случае нет.

Над группами может быть жёлтый блок с предупреждениями. Он значит: файл применится, но эти поля работают не так, как можно подумать. Например, правило итога у базы данных не сработает, а общее правило только со статусом получат все такие ошибки проекта. В каждой строке написано поле и что сделать. Применять файл предупреждения не мешают.

Если меняются условия среды или формат логов, строка отчёта предупредит, что идущие поиски этого проекта остановятся.

## Шаг 5. Примените

Нажмите «Применить N изменений». Кнопка есть, только если отчёт построен именно для этого текста и ошибок нет.

Файл применяется целиком. Если при записи что-то не сошлось, не меняется ничего: ни настройки, ни маскирование, ни методы.

После применения текст заменяется свежей выгрузкой. Комментарии и порядок ваших записей при этом пропадут: файл снова собран из базы.

Новые названия видны сразу, в том числе на уже открытых страницах при следующем обновлении.

## Что делает каждая правка

| Что вы сделали в тексте | Что будет |
|---|---|
| Стёрли запись: метод, систему, ошибку, правило, тип id | Запись остаётся и работает. В отчёте «нет в файле». После применения она снова появится в тексте |
| Стёрли поле внутри записи | Поле станет пустым: запись заменяется целиком. Отчёт покажет это в «Будет изменено» |
| Поставили записи `hidden: true` | Запись скрыта и больше не действует |
| Убрали `hidden: true` | Запись возвращается. Если её скрыл человек формой, нужно «Заменить ручные правки» |
| Поменяли `title`, `name`, `action` и другие обычные поля | Запись та же, поля новые |
| Поменяли `http`, `path` или `rpc` метода | Это новая запись. Старая осталась и работает: скройте её через `hidden: true` |
| Поменяли условия ошибки: `http`, `code`, `text` | То же: новая запись, старую скройте |
| Поменяли условия правила итога: `when` | То же: новая запись, старую скройте |
| Поменяли `key` системы или типа id | То же: новая запись. Если у системы есть хосты, проверка откажет: хост уже занят старой системой |
| Поменяли только имя подстановки: `{id}` на `{userId}` | Запись та же, путь обновится |
| Стёрли раздел `settings` | Настройки не меняются |
| Стёрли среду из `settings.environments` | Среда остаётся. Убирают её на форме «Среды» |
| Стёрли строку из `masking` | Этот вид маски не меняется |
| Стёрли `keys` у вида маски | Список добавленных полей этого вида станет пустым |
| Переставили записи или поля местами | Ничего: порядок в файле не хранится |
| Переставили среды | Порядок сред изменится: он хранится |
| Изменили только комментарии | Применять нечего: комментарии не хранятся |

> Перед тем как переносить запись из выгрузки в другой файл, переносите её со всеми полями. Строка `{ key: pay, name: Платёжный шлюз }` сотрёт у этой системы `hosts` и `description`. Методы и правила системы останутся: это отдельные записи.

## Ручные правки

Запись, которую правили или создали формой, считается ручной. Файл её не меняет, а показывает в группе «Ручные правки пропущены».

Запись, которую удалили формой, файл тоже не возвращает.

Чтобы заменить такие записи значениями из файла, включите «Заменить ручные правки» и дождитесь нового отчёта. После применения записи снова считаются записями файла.

На раздел `settings` этот переключатель не действует. От чужих правок настроек защищает сверка версии.

## Если проект изменили, пока вы правили

Это нормально: блокировок нет, правят все одновременно.

Страница помнит, с какой версии проекта открыт текст. Версия общая для справочника, маскирования, настроек и вида. Изменение другого проекта на неё не влияет.

- **Правок нет.** Текст заменяется свежим сам, страница об этом сообщает.
- **Правки есть.** Появляется сообщение «Проект изменили, пока вы правили». Ваш текст на месте, кнопки применения нет.

![Сообщение «Проект изменили, пока вы правили» с кнопками «Загрузить свежий файл» и «Оставить мои правки»](shot:file-page-conflict)

Дальше выбираете вы:

- «Загрузить свежий файл»: ваш текст заменится выгрузкой, правки пропадут. Страница спросит подтверждение. Чтобы не потерять правки, сначала нажмите «Скачать».
- «Оставить мои правки»: текст проверится заново. Отчёт покажет всё, что он изменит, включая откат чужих правок. Читайте его внимательно: всё, чего нет в вашем тексте, останется, а всё, что в нём другое, перепишет чужую правку.

Если вы успели нажать применение, сервер ответит отказом, ничего не запишет и покажет то же сообщение.

## YAML: где нужны кавычки

Большинство ошибок синтаксиса связано с тремя знаками: `*`, `{` и `:`. Ставьте кавычки в этих местах:

| Что пишете | Как писать | Почему |
|---|---|---|
| Любой HTTP-метод | `http: '*'` | Без кавычек `*` значит ссылку YAML |
| Шаблон хоста со звёздочкой | `'*.gateway.pay.example'` | То же |
| Код ошибки | `code: '00'` | Без кавычек YAML прочитает число |
| Значение статуса из цифр | `value: '2'` | Здесь нужен текст, число проверка не примет |
| Код партнёра | `partnerCode: '176'` | То же |
| Значение в `equals`, если важны нули | `equals: '00'` | Без кавычек это число 0, а `'00'` и `0` разные значения |
| Текст с подстановкой | `text: '{message}'` | Без кавычек `{` начинает объект YAML |
| Путь с `{}` внутри `{ … }` | `{ http: GET, path: '/v1/users/{id}', name: Клиент }` | То же |
| Текст с двоеточием и пробелом | `description: 'REST JSON. Успех: HTTP 200'` | Без кавычек YAML ищет новое поле |
| Условие «не равно» и `!~` | `op: '!='`, `op: '!~'` | Без кавычек `!` значит метку YAML |

Вот так писать нельзя, проверка откажет:

```yaml bad
version: 1
project: acme
systems:
  - key: pay
    name: Платёжный шлюз
    methods:
      - http: *
        path: /api/charge
        name: Списание
```

А так правильно:

```yaml full
version: 1
project: acme
systems:
  - key: pay
    name: Платёжный шлюз
    methods:
      - http: '*'
        path: /api/charge
        name: Списание
```

Ещё несколько правил:

- Отступы только пробелами. Табуляция даёт ошибку синтаксиса.
- Повтор поля в одной записи даёт ошибку синтаксиса.
- Ссылками YAML (`&` и `*`) лучше не пользоваться. Больше 100 ссылок дают ошибку.

## JSON

Структура та же, что в YAML, поля те же. Первое поле может быть ссылкой на схему.

```json full
{
  "$schema": "./catalog.schema.json",
  "version": 1,
  "project": "acme",
  "systems": [
    {
      "key": "pay",
      "name": "Платёжный шлюз",
      "hosts": ["gateway.pay.example:8443"],
      "methods": [
        { "http": "POST", "path": "/api/charge", "name": "Списание" }
      ]
    }
  ]
}
```

В JSON нет комментариев. Лишняя запятая даёт ошибку синтаксиса. Повтор поля в JSON ошибкой не считается: действует последнее значение, а проверка предупредит и назовёт путь.

## Подсказки в редакторе кода

Первая строка выгрузки в YAML подключает схему:

```yaml part
# yaml-language-server: $schema=./catalog.schema.json
```

Откройте схему кнопкой «Схема формата» и сохраните её рядом с файлом под именем `catalog.schema.json`. Редактор начнёт подсказывать поля и подчёркивать неизвестные.

Схема ловит форму записи, но не всё. Ссылки на другие записи, разбор `regex`, номер карты в тексте и права проверяет только сервер. Поэтому проверка на странице нужна, даже если редактор ничего не подчеркнул.

## Командная строка

Команды запускаются из корня репозитория. Нужен доступ к файлу настроек и адрес базы в `THREADLINE_DATABASE_URL`.

```bash
pnpm threadline:catalog export acme acme-now.yaml             # выгрузить
pnpm threadline:catalog import acme my.yaml --dry-run         # проверить без записи
pnpm threadline:catalog import acme my.yaml                   # применить
pnpm threadline:catalog import acme my.yaml --dry-run --force # проверить с заменой ручных правок
pnpm threadline:catalog schema catalog.schema.json            # записать схему
```

Что отличается от страницы:

- **Ролей нет.** Право определяет доступ к файлу настроек и базе. Команда меняет все разделы.
- **Версия не сверяется.** Открытого текста у команды нет, поэтому она может молча откатить чужую правку. Выгружайте файл прямо перед правкой и всегда начинайте с `--dry-run`.
- **Видно не сразу.** Работающий сервер увидит изменения за 30 секунд.
- **Первые 200 строк.** В каждой группе отчёта показаны первые 200 строк.
- **Предупреждения.** Отчёт перечисляет их отдельным списком. Код выхода они не меняют.

| Код выхода | Что значит |
|---|---|
| 0 | Всё прошло или проверка без ошибок |
| 1 | Ошибка в файле или в аргументах |
| 2 | База недоступна или её адрес не задан |

Если база ещё ни разу не видела сервер, записи проекта в ней нет. Тогда `export` пишет файл без `settings` и предупреждает, а `import` файла с `settings` даёт ошибку.

## Выгрузка как начальный набор

Файл `config/catalog/<проект>.yaml` сервер загружает сам при подключении к базе. Выгрузку можно положить туда как есть. Разделы `settings` и `masking` он пропустит, остальное применит, а в журнале будет предупреждение. Настройки и маски другой среды такой файл не изменит.

## Через API

Для скриптов есть те же действия:

| Что | Запрос |
|---|---|
| Выгрузить | `GET /api/projects/acme/catalog/export?format=yaml`, версия в заголовке `X-Project-File-Version` |
| Проверить | `POST /api/projects/acme/catalog/import?dryRun=1`, версия в поле `version` отчёта |
| Применить | `POST /api/projects/acme/catalog/import?baseVersion=<версия>` |
| Узнать версию | `GET /api/projects/acme/file-version` |
| Схема | `GET /api/catalog/schema` |

Без `baseVersion` применение отвечает 400. Устаревшая версия: ответ 409 `project-file-conflict`, ничего не записано. Ошибки в файле: ответ 422 с отчётом. Файл больше 2 МБ: ответ 413.

# Сообщения проверки

Здесь все сообщения, которые может показать проверка файла, и что с ними делать. Найдите своё по тексту: поиск браузера работает.

Сообщение состоит из пути и текста. Путь говорит, где ошибка: `systems.1.methods.3.path` значит вторая система, четвёртый метод, поле `path`. Счёт идёт с нуля.

Знак `…` в сообщении значит подставленное значение. Значений, которые скрыла бы маска, в сообщениях нет. Если интерфейс не на русском, текст может быть переведён.

Ошибка не даёт применить файл. Предупреждение не мешает: файл применится, но поле не действует. Предупреждения собраны в своём разделе ниже.

## Синтаксис

Текст не удалось прочитать как YAML или JSON. Дальше он не проверяется.

| Сообщение | Что сделать |
|---|---|
| `файл не разбирается как YAML: …` | Смотрите строку и столбец. Частые причины: отступ, табуляция, `*` или `{` без кавычек, двоеточие с пробелом в тексте без кавычек, повтор поля. Таблица кавычек: «Как работать с файлом» |
| `файл не разбирается как JSON: …` | Смотрите позицию. Частые причины: лишняя запятая, одинарные кавычки, комментарий |
| `Ошибка синтаксиса: строка …, столбец …. Такой текст не проверяется на сервере.` | То же, сообщение страницы в браузере |
| `Ошибка синтаксиса: текст не разбирается, например слишком глубокая вложенность или лишние ссылки. Такой текст не проверяется на сервере.` | Позицию назвать нельзя. Уберите ссылки YAML `&` и `*`, проверьте вложенность |
| `файл больше … МБ` | Предел 2 МБ. Разбейте файл по системам: каждый применяется отдельно |

## Весь файл

| Сообщение | Что сделать |
|---|---|
| `файл справочника — объект YAML или JSON с полями version и project` | Текст пуст или это не объект. Начните с `version: 1` и `project: acme` |
| `поддерживается версия формата …` | Напишите `version: 1`, числом, без кавычек |
| `файл проекта «…», а загрузка в справочник «…»` | В поле `project` другой проект. Напишите идентификатор открытого проекта |
| `неизвестное поле` | Такого поля нет в формате: опечатка или лишнее поле. Путь назовёт его. Сверьте с таблицей «Все поля» |
| `неизвестное поле «…»` | То же в разделе `settings`. Токенов, адресов и логотипов в файле нет |
| `обязательное поле: допишите его` | Поля нет, а без него запись не работает. Путь назовёт его |
| `Неверный ввод: ожидалось …, получено …` | Поле другого типа. `получено число` значит, что нужны кавычки. `получено object` у `text` значит, что `{message}` написан без кавычек |
| `Неверный вариант: ожидалось одно из …` | Значения нет в списке допустимых. Напишите одно из названных |
| `Слишком большое значение: …` | В списке больше элементов, чем можно |
| `неверный тип значения` | Значение не того вида. Например, у `when.http` нужно число, диапазон или список |
| `поле не может быть пустым` | Заполните поле или уберите его, если оно необязательно |
| `не длиннее … символов` | Сократите текст. Предел назван в сообщении |
| `не короче … символов` | Подстрока `text` от 3 символов. Возьмите более длинный кусок |
| `уберите номер карты, секрет или значение другого вида маски: маскирование скрыло бы часть текста` | В тексте значение, похожее на настоящее: номер карты, телефон, паспорт. Уберите. Самого значения в сообщении нет, смотрите путь |

## Раздел idTypes

| Сообщение | Что сделать |
|---|---|
| `ключ типа: латиница в нижнем регистре, цифры и «_», с буквы, до 32 символов` | Исправьте `key`: `qr_payment`, а не `QR-Payment` |
| `вид типа: entity или operation` | Исправьте `kind` |
| `у сущности нет словаря статусов` | Уберите `statuses` или поставьте `kind: operation` |
| `статус уже есть в словаре` | Значения сравниваются без учёта регистра. Уберите повтор |
| `итог статуса: pending, success или failure` | Исправьте `outcome` статуса |
| `не больше … статусов` | В словаре до 30 значений |
| `тип «…» повторяется: та же запись в …` | Два типа с одним `key`. Оставьте один |
| `тип «…» используется в методах (…): скрыть нельзя` | Сначала уберите ссылки на тип из методов |

## Раздел systems

| Сообщение | Что сделать |
|---|---|
| `ключ системы: строчные латинские буквы, цифры и дефис, до 32 символов` | Исправьте `key` |
| `вид системы: project или external` | Исправьте `kind` |
| `тип системы: service, database или queue` | Исправьте `type` |
| `система-автор (kind: project) в файле одна` | Система самого проекта одна. Уберите `kind: project` у второй |
| `ключ системы-автора равен id проекта «…»` | Напишите в `key` идентификатор проекта |
| `система с ключом проекта — система-автор: нужен kind: project` | Добавьте `kind: project` |
| `система-автор — сервис` | Уберите `type` у системы проекта |
| `систему-автора нельзя скрыть: без неё входы проекта остаются неизвестными` | Уберите `hidden: true` |
| `система «…» повторяется: та же запись в …` | Две системы с одним `key`. Оставьте одну |
| `шаблон хоста: host, host:port, [ipv6]:port или *.domain` | Только хост и порт, без `https://` и пути. У `*.domain` в домене нужна точка |
| `шаблон хоста повторяется` | Уберите повтор. Регистр не важен |
| `хост уже у системы «…»` | Один шаблон у одной системы. Если вы поменяли `key`, это новая система: верните прежний ключ |
| `у базы данных и шины сообщений нет методов` | Уберите `methods` или поставьте `type: service` |
| `у системы … методов в справочнике: у базы данных и шины сообщений методов нет` | У системы уже есть методы в проекте. Оставьте `type: service` |

## Методы

| Сообщение | Что сделать |
|---|---|
| `HTTP-метод: …` | Заглавными: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS` или `'*'` |
| `шаблон пути начинается с «/», без «?», «#» и пробелов` | Уберите строку запроса. Параметры запроса в путь не пишут, id из них берут через `fields` |
| `пустая часть пути: «//» или «/» в конце пути` | Уберите лишнюю `/`. Корень пишется `/` |
| `подстановка занимает всю часть пути между «/»: /cards/{cardId}, а не /cards/id{cardId}` | Часть пути либо вся буквальная, либо вся `{имя}`. `/files/{name}.json` так не записать: это вопрос в список |
| `имя подстановки: латиница, цифры, «_» и «-»` | Исправьте имя внутри `{}` |
| `путь длиннее … символов` | Предел 512 символов |
| `действие: латинские буквы, цифры, «_», «.», «:» и «-»` | Исправьте `rpc` |
| `вид метода: call, start, status или callback` | Исправьте `kind` |
| `колбэк бывает только у системы-автора` | Перенесите метод в систему проекта |
| `у этого вида метода нужен тип операции` | Добавьте `op`: `start`, `status` и `callback` без него не бывают |
| `типа «…» нет: сначала заведите его в «Идентификаторах»` | Добавьте тип в `idTypes` этого файла или заведите его формой |
| `тип «…» — сущность, а нужен тип операции` | В `op` нужен тип с `kind: operation` |
| `где поле: query, request или response` | Исправьте `in` в `fields` |
| `не больше … полей id` | У метода до 10 полей `fields` |
| `где статус: request или response` | Исправьте `in` в `status` |
| `поле статуса бывает только у метода с типом операции` | Добавьте `op` или уберите `status` |
| `значения «…» нет в словаре статусов типа «…»` | Правая часть `map` должна быть в `statuses` этого типа |
| `путь поля: имена через точку, например data.status` | Без скобок и индексов массива. В массив заходить нельзя |
| `путь поля не длиннее … символов` | Предел 128 символов |
| `метод … повторяется: та же запись в …` | Одинаковые `http`, `path` и `rpc`. Имена подстановок не считаются: `{id}` и `{userId}` это один метод |
| `это поле маскируется: номер карты, секрет или заголовок авторизации нельзя показывать и сравнивать` | Такое поле нельзя делать id, статусом и условием сравнения. Можно только `exists` |
| `это поле маскируется: значение вида маски нельзя показывать и сравнивать` | То же для полей с личными данными: `phone`, `passport`, `accountId` и другие |

## Правила ошибок

| Сообщение | Что сделать |
|---|---|
| `нужно хотя бы одно условие: HTTP-статус, код или подстрока` | Добавьте `http`, `code` или `text` |
| `HTTP-статус от 100 до 599` | Исправьте `http` |
| `HTTP-статус — целое число` | Без дробной части |
| `код не длиннее … символов` | Предел 64 символа |
| `важность: error или ok` | Исправьте `severity` |
| `у системы «…» нет метода …` | Ссылка `method` должна совпасть с методом этой системы по `http`, `path` и `rpc`. Частая причина: забыт `rpc` или метод описан как `'*'` |
| `правило ошибки с теми же условиями повторяется: та же запись в …` | Одинаковые уровень, `http`, `code` и `text`. `'00'` и `'0'` это один код |

## Правила итога

| Сообщение | Что сделать |
|---|---|
| `нужно хотя бы одно условие: HTTP-статус или поле` | Заполните `when` |
| `итог: success, error, pending или ignore` | Исправьте `outcome` или допишите его |
| `начало диапазона больше конца` | Поменяйте местами `from` и `to` |
| `у условия ровно одна проверка: equals, oneOf, exists или regex` | Оставьте одну проверку на условие. Нужно две: два условия |
| `где поле: response или request` | Исправьте `in`. У условий нет `query` |
| `не больше … условий на поля` | В правиле до 10 условий |
| `не больше … значений` | В `oneOf` до 50 значений |
| `значение не длиннее … символов` | В `equals` и `oneOf` до 200 символов |
| `выражение не длиннее … символов` | В `regex` до 200 символов |
| `приоритет от 1 до 1000` | Исправьте `priority` |
| `текст не длиннее … символов` | В `text` до 200 символов |
| `незакрытая или пустая «{»: место подстановки пишется {путь}` | Закройте скобку. В тексте без подстановок скобок быть не должно |
| `не больше … мест подстановки` | В `text` до 5 мест `{путь}` |
| `в шаблоне: …` | В `{путь}` поле, которое скрывает маска. Уберите его |
| `правило итога с теми же условиями повторяется: та же запись в …` | Одинаковые уровень и `when`. Оставьте одно. Итог не считается: два правила с теми же условиями и разными итогами это повтор |

Сообщения о выражении `regex`:

| Сообщение | Что сделать |
|---|---|
| `выражение не компилируется: …` | Ошибка в записи выражения: незакрытая скобка и подобное |
| `просмотр вперёд или назад: хранилище такое выражение не выполнит` | Уберите `(?=`, `(?!`, `(?<=`, `(?<!` |
| `обратная ссылка: хранилище такое выражение не выполнит` | Уберите `\1` и `\k` |
| `флаги допускаются только в начале выражения: (?i), (?s) или (?is)` | Перенесите флаг в начало |
| `имена групп повторяются` | Переименуйте группу |
| `повтор … больше …: хранилище такое выражение не выполнит` | Предел повтора `{n}` 1000 |
| `класс POSIX [[:…:]] JS не понимает; перечислите символы классом` | Вместо `[[:digit:]]` напишите `[0-9]` |

## Раздел masking

| Сообщение | Что сделать |
|---|---|
| `вид нельзя скрыть, только выключить` | Уберите `hidden`, поставьте `enabled: false` |
| `у вида «…» нет выключателя` | `card_number` и `secrets` всегда включены |
| `вид маскирования повторяется: та же запись в …` | Один вид в одной строке |
| `имя поля: от 1 до 64 символов, латиница, цифры, «_», «.», «:» и «-»` | Исправьте имя в `keys` |
| `поле уже есть в списке` | Уберите повтор. `client_mobile` и `clientMobile` это одно поле |
| `поле уже есть у вида «…»` | Поле принадлежит другому виду. Добавлять его не нужно: оно уже скрыто |

## Раздел settings

Сообщения те же, что на формах. Путь начинается с `settings`.

| Сообщение | Что сделать |
|---|---|
| `название не может быть пустым` | Заполните `name` |
| `название длиннее … символов` | До 80 символов |
| `в названии есть управляющие символы` | Уберите перенос строки или табуляцию |
| `название похоже на скрываемые данные, например номер карты: такое значение не сохраняется` | Уберите такое значение |
| `неизвестный часовой пояс, нужно имя из базы часовых поясов, например Europe/Berlin` | Напишите имя пояса, например `Europe/Berlin` |
| `срок хранения: целое число дней от 1 до 400` | Исправьте `retentionDays` |
| `формата логов «…» нет: известные форматы — …` | Напишите одно из названных имён |
| `формат логов указывается именем: известные форматы — …` | В `format` только имя. Само описание формата живёт в файле настроек |
| `нужна хотя бы одна среда` | У проекта нет сред. Добавьте среду |
| `в проекте не больше … сред` | До 50 сред |
| `идентификатор среды «…» повторяется` | Уберите повтор |
| `идентификатор: строчные латинские буквы, цифры и дефис, до 32 символов` | Исправьте `id` |
| `идентификатор … не может состоять только из цифр: порядок такой записи не сохранился бы` | Добавьте букву в `id` |
| `идентификатор среды «catalog» занят справочником: выберите другой` | Другой `id` |
| `идентификатор среды «settings» занят настройками проекта: выберите другой` | Другой `id` |
| `хранилища «…» нет в файле настроек, известные: …` | В `backend` только имя из этого списка |
| `форма не сохраняет условия для хранилища «…», пока в файле настроек не задана граница: …` | Администратор сервера добавляет `formScope` в файл настроек. В самом файле проекта это не исправить |
| `значение вне границы хранилища: …` | Напишите значение из разрешённых |
| `шаблон стенда вне границы хранилища: …` | То же для шаблона стенда |
| `нужно условие равенства на метку …: …` | Добавьте условие `=` на эту метку |
| `у среды «…» нет условий` | Добавьте в `selector` условие `=` |
| `среде «…» нужно хотя бы одно условие равенства (op: "=") с непустым значением, чтобы не читать логи за пределами проекта` | Добавьте условие `=` с непустым значением |
| `в среде не больше … условий` | До 20 условий |
| `два разных равенства на метку …: такая среда всегда пуста` | Оставьте одно `=` на метку |
| `имя метки: латинские буквы, цифры и подчёркивание` | Исправьте `label` |
| `метки с двумя подчёркиваниями в начале служебные: форма их не принимает` | Возьмите другую метку |
| `значение длиннее … символов` | До 256 символов |
| `в значении есть управляющие символы` | Уберите их |
| `пробел на краю значения: такое значение почти всегда опечатка и даёт пустой результат` | Уберите пробел |
| `searchOnly бывает только у условия «не равно» (op: "!="): исключение для обычного поиска не расширяет границы проекта` | Уберите `searchOnly` или поставьте `op: '!='` |
| `поле stand бывает только у среды стендов (kind: pr-stands)` | Уберите `stand` или поставьте `kind: pr-stands` |
| `у среды стендов «…» нет поля stand с меткой и шаблоном` | Добавьте `stand` |
| `шаблон стенда должен содержать ровно одно место для номера …, например pr-{number}` | В `template` ровно один `{number}` |
| `в шаблоне стенда допустимы латинские буквы, цифры, точка, дефис и подчёркивание` | Уберите другие знаки |
| `у шаблона стенда нет постоянной части: он читал бы любое числовое значение метки` | Добавьте постоянный текст: `acme-pr-{number}` |
| `этот элемент нельзя выключить` | Колонки `time`, `request` и `outcome` всегда `true` |
| `нераспознанная запись видна только в сырых записях` | `blocks.raw.full` всегда `true` |
| `вкладка по умолчанию выключена в обоих режимах` | Выберите другой `defaultTab` или включите вкладку |

## Права

| Сообщение | Что сделать |
|---|---|
| `раздел настроек меняют только аналитик и администратор: файл не применён` | Верните `settings` как в выгрузке или уберите раздел. Или попросите Аналитика |
| `раздел маскирования меняет только администратор: файл не применён` | Верните `masking` как в выгрузке или уберите раздел. Или попросите Администратора |

Сервер может отказать и всей роли: `Сервер отказал: у вашей роли нет права проверять файл. Текст на месте, его можно скачать.` Так бывает, если роль понизили, пока вы правили.

## При применении

| Сообщение | Что сделать |
|---|---|
| `Проект изменили, пока вы правили` | Описано на странице «Как работать с файлом» |
| `файл не применён: …` | Запись не нашлась или столкнулась с другой. Ничего не записано. Проверьте заново и повторите |
| `записи файла конфликтуют со справочником (…)` | Запись файла упёрлась в запись базы. Ничего не записано. Выгрузите свежий файл и сравните |
| `записи проекта в базе ещё нет: раздел settings применить не к чему` | Сервер ещё ни разу не запускался на этой базе. Запустите сервер или уберите `settings` |
| `Выгрузка отклонена: маскирование скрыло бы значения в этих полях, поэтому текста нет.` | В базе есть значение, которое скрыла бы маска. Исправьте его формой в разделе справочника или настроек |

## Предупреждения

Файл применится. Поле принято, но работает не так, как можно подумать. Предупреждения видны рядом с ошибками, если те есть. Скрытые записи предупреждений не дают.

| Сообщение | Что сделать |
|---|---|
| `поле повторяется: действует последнее значение. Оставьте одно` | В JSON поле написано дважды. Первое значение пропало. Оставьте нужное. В YAML так бывает только с `1` и `'1'` в `status.map` |
| `у входа в проект действие не читается: на входе этот метод не сработает. Оставьте на этом адресе один метод без rpc` | Уберите `rpc` у метода системы проекта и заведите один метод с общим названием |
| `отдельных шагов шины в логах Threadline не находит: система видна в справочнике и на HTTP-вызовах на её хост. Если это HTTP-сервис, уберите type` | Запись можно оставить как подпись. Если система отвечает по HTTP, уберите `type` |
| `правила итога проверяются только на HTTP-ответах: у записи базы данных и шины ответа нет, это правило не сработает. Уберите его` | Уберите правило. Текст ошибки базы задают в `errors` через `text` |
| `у записи базы нет HTTP-статуса: правило с этим условием не сработает. Уберите http` | Оставьте в правиле `text` или `code` |
| `одного HTTP-статуса в общем правиле мало: этот текст получат все такие ошибки проекта. Добавьте text или code` | Файл применится, правило будет работать на весь проект. Лучше добавьте `text` или `code`. Форма в «Общих правилах» новую запись только со статусом не сохранит |
| `в подстроке скрытая часть, «…» или звёздочки: в тексте ошибки её нет, и правило не сработает. Оставьте только постоянную часть` | Оставьте в `text` только постоянную часть. Форма такую подстроку не сохранит |
| `типы вида entity (…) на страницах запроса и операции не показываются: они видны только в разделе «Идентификаторы». Нужна кнопка «Открыть операцию»: поставьте kind: operation. Иначе ничего делать не нужно` | Для клиента или карты ничего делать не нужно. Для платежа или перевода поставьте `kind: operation` |
| `начальный набор не меняет настройки: раздел settings пропущен, остальное применено. Настройки меняют на странице «Файл проекта»` | Бывает только в журнале сервера. Ничего делать не нужно: начальные настройки даёт файл настроек |
| `начальный набор не меняет маскирование: раздел masking пропущен, остальное применено. Маскирование меняет администратор на странице «Файл проекта»` | Бывает только в журнале сервера. Ничего делать не нужно: новая база получает встроенные маски |

## Командная строка

| Сообщение | Что сделать |
|---|---|
| `файл не читается: …` | Проверьте путь. Команды запускаются из корня репозитория |
| `проекта «…» нет в …` | Такого проекта нет. Команда назовёт существующие |
| `THREADLINE_DATABASE_URL не задан: справочник выключен.` | Задайте адрес базы в окружении или в `.env` |
| `база справочника недоступна (…): …` | Проверьте подключение к базе. Код выхода 2 |

# Методы

Метод: адрес системы с понятным названием. Запись метода говорит: вызов `POST /api/charge` называется «Списание». Методы лежат внутри системы, в списке `methods`.

## Пример

```yaml full
version: 1
project: acme
idTypes:
  - key: order
    kind: operation
    name: Заказ
    statuses:
      - { value: NEW, name: Создан, outcome: pending }
      - { value: PAID, name: Оплачен, outcome: success }
      - { value: DECLINED, name: Отклонён, outcome: failure }
systems:
  - key: acme
    kind: project
    name: Acme Pay
    methods:
      - http: GET
        path: /v1/users/{userId}/orders/{orderId}
        name: Данные заказа
        domain: Заказы
  - key: pay
    name: Платёжный шлюз
    hosts:
      - gateway.pay.example:8443
    methods:
      - http: POST
        path: /api/charge
        name: Списание
        description: Списывает сумму с карты клиента
        kind: start
        op: order
        fields:
          - { in: response, path: data.order_ref, type: order }
      - http: GET
        path: /api/charge/{orderId}
        name: Статус списания
        kind: status
        op: order
        status: { in: response, path: data.state }
```

## Поля

| Поле | Обязательно | Что писать | Где видно |
|---|---|---|---|
| `http` | да | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS` заглавными или `'*'` | Метка в строке метода, условие поиска метода |
| `path` | да | Шаблон пути | Строка метода в справочнике, условие поиска метода |
| `rpc` | нет | Действие SOAP или JSON-RPC | Условие поиска метода |
| `name` | да | Название, до 80 символов | Схема, список запросов, причины ошибки, блок «Итог» |
| `domain` | нет | Группа, например «Карты», до 40 символов | Только в списке методов справочника и в его поиске |
| `description` | нет | Что делает метод, до 500 символов | Только в форме метода и в поиске справочника |
| `kind` | нет | `call`, `start`, `status`, `callback`. По умолчанию `call` | Метка в списке методов, строка в блоке «Итог» |
| `op` | у `start`, `status`, `callback` | Ключ типа вида `operation` | Блок «Итог», страница операции |
| `fields` | нет | Id не в пути | Кнопка «Открыть операцию» |
| `status` | нет | Где лежит статус операции | Блок «Итог», страница операции |
| `hidden` | нет | `true`: метод не действует | Шаг снова подписан путём |

Поля `op`, `fields` и `status` описаны на странице «Id и операции».

## Как Threadline находит метод

Threadline не хранит логи. Он читает записи и для каждой на лету ищет метод. Поэтому правка файла сразу действует на старые записи.

![Как находится метод: вход ищется только в системе проекта, вызов сначала ищет систему по хосту, затем метод по HTTP-методу, пути и действию](diagram:file-method)

Вход: запрос, который пришёл в ваш проект. Вызов: запрос, который ваш проект отправил в другую систему.

**Вход.** Метод ищется только среди методов системы самого проекта. Хост не важен: вход через шлюз и вход прямо в приложение получат одно название.

**Вызов.** Сначала Threadline ищет систему:

1. Хост подошёл к шаблону системы: берутся методы только этой системы.
2. Хост не подошёл или его нет в адресе: берутся методы всех внешних систем. Если подошли методы ровно одной системы, это она.
3. Подошли методы нескольких систем или ни одной: система неизвестна, шаг подписан хостом и путём.

**Метод внутри системы.** Сравниваются HTTP-метод, путь и действие:

- `http` равен методу записи, или в файле `'*'`.
- Путь совпал с шаблоном.
- Действие совпало с `rpc`, если оно есть.

**Если система узнана, а метод нет.** Шаг подписан именем системы и путём. Строка попадает в «Неизвестное» справочника.

## Шаблон пути

Путь делится косыми чертами на части. Каждая часть в шаблоне либо написана буквально, либо занята подстановкой `{имя}`.

| Правило | Шаблон | Адрес из лога | Подходит |
|---|---|---|---|
| Подстановка принимает любую непустую часть | `/v1/users/{userId}` | `/v1/users/12345` | да |
| Число частей должно совпасть | `/v1/users/{userId}` | `/v1/users/12345/cards` | нет |
| Пустая часть не подходит | `/v1/users/{userId}/cards` | `/v1/users//cards` | нет |
| Регистр важен | `/v1/Users` | `/v1/users` | нет |
| Строка запроса не считается | `/v1/users` | `/v1/users?page=2` | да |
| Косая черта в конце адреса не считается | `/v1/users` | `/v1/users/` | да |
| Корень пишется одной чертой | `/` | `https://rpc.pay.example/` | да |

Как писать шаблон:

- Начинается с `/`.
- Без `?`, `#` и пробелов.
- Без `/` в конце и без `//`. Исключение: корень `/`.
- Подстановка занимает часть целиком. `/cards/{cardId}` можно, `/cards/id{cardId}` и `/files/{name}.json` нельзя.
- Имя подстановки: латиница, цифры, `_` и `-`, не с цифры.
- Полный путь, как в логе. Сваггер с `servers: https://gateway.pay.example/gw/v2` и путём `/payments` даёт `/gw/v2/payments`.
- До 512 символов.

Имя подстановки на выбор метода не влияет, оно задаёт тип id. `/v1/users/{id}` и `/v1/users/{userId}` это один и тот же метод: две такие записи в файле дадут ошибку о повторе.

## Если подошло несколько

Выигрывает более точный, по порядку:

1. На первом различии буквальная часть сильнее подстановки: `/cards/unmask` сильнее `/cards/{cardId}`.
2. Точный HTTP-метод сильнее `'*'`.
3. Запись, созданная раньше.

```yaml part
methods:
  - { http: GET, path: '/v1/users/{userId}/cards/{cardId}', name: Данные карты }
  - { http: GET, path: '/v1/users/{userId}/cards/unmask', name: Открыть номер карты }
```

Запрос `GET /v1/users/42/cards/unmask` получит название «Открыть номер карты», а `GET /v1/users/42/cards/777` название «Данные карты».

## Действие: поле rpc

У JSON-RPC и SOAP один адрес на всё, а действие лежит в теле. Для них одного пути мало. Каждое действие это своя запись с полем `rpc`.

```yaml full
version: 1
project: acme
systems:
  - key: cards
    name: Карточный процессинг
    hosts:
      - rpc.pay.example
    methods:
      - { http: POST, path: /, rpc: card.info, name: Данные карты }
      - { http: POST, path: /, rpc: p2p.transfer, name: Перевод }
  - key: core
    name: Платёжное ядро
    hosts:
      - core.pay.example:8443
    methods:
      - { http: POST, path: /ws/Issuing, rpc: getCardList, name: Список карт }
```

Где Threadline берёт действие:

| Вид | Откуда | Пример тела | Значение `rpc` |
|---|---|---|---|
| JSON-RPC | Поле `method`. В теле обязано быть поле `jsonrpc` | `{"jsonrpc":"2.0","method":"card.info"}` | `card.info` |
| SOAP | Первый элемент внутри `Body`, без префикса | `<soap:Body><ns:getCardList/></soap:Body>` | `getCardList` |
| SOAP, только ответ | То же, без окончания `Response` | `<soap:Body><ns:getCardListResponse/></soap:Body>` | `getCardList` |

Как выбирается запись:

- Действие есть, и нашлась запись с таким `rpc`: это она.
- Действие есть, а записи с таким `rpc` нет: берётся запись этого пути без `rpc`.
- Действия нет: берётся только запись без `rpc`.

Отсюда ловушка. Запись без `rpc` на таком адресе получит все незнакомые действия, и они будут подписаны чужим названием. Не заводите её.

Тело с полем `method`, но без `jsonrpc`, действием не считается.

> Поле `rpc` работает только на вызовах. Для входа в проект действие не читается: метод системы проекта с `rpc` на входе не сработает. Файл применится, а проверка предупредит. Если ваш проект сам принимает JSON-RPC или SOAP на одном адресе, заведите один метод без `rpc` с общим названием.

Правило ошибки или итога для такого метода указывает `rpc` в ссылке: `method: { http: POST, path: /, rpc: p2p.transfer }`.

## Виды метода: kind

Вид говорит, какую роль метод играет в операции. Цвет шага и статус запроса он не меняет.

| Значение | Что значит | Подпись у проекта | Подпись у внешней системы |
|---|---|---|---|
| `call` | Обычный вызов. Значение по умолчанию | «Обычный» | «Синхронный» |
| `start` | Создаёт операцию | «Создание операции» | «Асинхронная отправка» |
| `status` | Отдаёт статус операции | «Статус операции» | «Статус» |
| `callback` | Внешняя система сама сообщает результат проекту | «Колбэк» | не бывает |

У `start`, `status` и `callback` обязательно поле `op`. Вид `callback` бывает только у системы проекта.

## Название

Пишите так, чтобы поняла поддержка: «Списание», «Данные карты», «Статус перевода». Без кодов и аббревиатур, если есть слово.

В названии и описании нельзя указывать номера карт, телефоны и другие значения, которые скрыла бы маска.

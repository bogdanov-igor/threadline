# Поиск

## Что вставить

Вставьте значение в поле «Значения для поиска» и нажмите Enter или запятую. Значение станет меткой. Слева на метке написано, что Threadline в нём узнал: «номер карты», «телефон», «UUID», «текст».

![Поле поиска с тремя метками: номер карты под маской, текст, телефон](shot:guide-search-values)

| Что есть в обращении | Что найдётся |
|---|---|
| ID запроса | Один этот запрос |
| id пользователя | Запросы по этому пользователю |
| id карты или токен карты | Запросы по этой карте |
| Номер карты или его маска | Запросы, где встречается эта карта |
| Телефон | Записи с этим номером в любом написании |
| id платежа или перевода | Запросы этой операции |
| Любой текст | Записи с этим текстом, например название метода |

Правила поля:

- Значений можно до пяти. В одной записи должны быть все сразу. Как несколько `|=` в Grafana.
- Большие и маленькие буквы различаются.
- Каждое значение не короче 2 символов. Хотя бы одно не короче 6: короткие встречаются слишком часто.
- Кавычки и обратная косая черта не подойдут.

### Номер карты

В поле номер сразу становится маской. В хранилище логов уходят только первые 6 и последние 4 цифры, а полное совпадение Threadline проверяет сам. Другая карта с теми же краями в список не попадёт.

Можно искать и по маске, например `411111******7893`. У таких запросов будет пометка «неточное совпадение»: одной маске подходят несколько карт.

После перезагрузки страницы номер нужно ввести заново. Threadline его не хранит.

### Телефон

Вставляйте в любом виде: с кодом страны и без, с пробелами и скобками. В метке номер будет цифрами с кодом страны, например `447700…`.

Маску телефона искать нельзя: `********0101` ничего не найдёт. Нужен полный номер.

## Период

Выберите «15 мин», «1 ч», «6 ч» или «24 ч». По умолчанию стоит 6 часов.

Для другого времени нажмите «Свой». Там два способа:

- **«Границы».** Укажите «Начало» и «Конец».
- **«Вокруг времени».** Вставьте время из лога и выберите отступ: ±5, ±15, ±30 или ±60 минут. Подойдёт `2026-11-02 16:20:29`, `02.11 16:20` или `16:20`.

![Окно «Свой период»: выбрано «Вокруг времени», время 10:30, отступ ±15, ниже получившиеся границы](shot:guide-search-period)

Нажмите «Применить», затем «Найти». Сам поиск не запускается.

Два ограничения:

- Один поиск охватывает не больше 24 часов.
- Логи хранятся ограниченное время. Срок написан на странице поиска, под списком «Что можно искать». Старше этого срока записей нет.

Время везде показано по часовому поясу проекта, а не вашего компьютера.

## Среда

Выбор среды стоит слева от поля. По умолчанию поиск идёт в одной выбранной среде.

![Открытый список сред: Prod, Test, PR stands, Demo, справа флажки «Искать и здесь», ниже состояние подключения и «Проверить снова»](shot:guide-search-env)

- Сменили среду: значения и период остались, результаты убрались. Нажмите «Найти» снова.
- Подпись «не настроено»: поиск в этой среде закрыт. Выберите другую и сообщите администратору.
- «PR stands»: временные копии сервиса для проверки изменений. Выберите номер в списке или введите его.

### Несколько сред сразу

Обращение могло пройти через несколько сред, например через прод и тест. Их можно искать одним поиском.

1. Откройте список сред.
2. Поставьте флажок справа от каждой нужной среды. Нажатие на название, как и раньше, выбирает одну среду.
3. Закройте список и нажмите «Найти».

На выборе среды появится, например, «Prod +1». Полный список виден в подсказке.

- Сред можно выбрать до пяти. Стенды PR и ненастроенные среды с другими не сочетаются.
- Результаты идут одним списком. У каждой строки метка её среды.
- Один и тот же ID запроса в двух средах даёт две строки: у каждой свои записи и свой итог.
- Строка открывает запрос в своей среде. «К результатам» вернёт к общему списку.
- Под итогом строка сред: сколько запросов нашлось в каждой или что с ней случилось.
- Если одна среда не ответила, найденное в других остаётся на экране. Сообщение называет среду, «Повторить» запускает поиск по всем средам заново.
- Во вкладке «Все записи» строки одной среды. Среда выбирается над строками.
- Короткая ссылка хранит все среды поиска.

## «Уточнить» и «Не содержит»

Условие убирает из результатов ненужное значение.

1. Нажмите «Уточнить» под полем поиска.
2. В поле «Не содержит» вставьте значение и нажмите Enter.
3. Нажмите «Найти».

![Открыто поле «Не содержит» с одной меткой](shot:guide-search-exclude)

На вкладках условие работает по-разному:

- **«Запросы».** Запроса нет в списке, если значение есть хотя бы в одной его записи.
- **«Все записи».** Убираются только строки с этим значением. Это `!=` из Grafana.

Что ещё важно:

- Значений можно до пяти, каждое не короче 2 символов.
- Значение не должно совпадать с тем, что вы ищете: результат был бы пуст.
- Открытый запрос показан целиком: условие на него не действует. Статус, шаги и ссылка на запрос те же, что и без условия.
- Запись далеко от найденных строк поиск не читает: если значение есть только в ней, запрос останется в списке.
- Короткая ссылка на результаты хранит условие и работает так же.

## Фильтры результатов

Фильтры стоят над списком и работают только по уже найденному. В хранилище логов ничего не уходит.

- **«Только с ошибкой».** Оставляет запросы с ошибкой. Если ошибок нет, переключатель недоступен.
- **«Фильтр».** Метод, система, компонент. Компонент: часть сервиса, которая написала запись.

Пока фильтр действует, над списком написано «Скрыто фильтрами: N». Кнопка «Сбросить» возвращает всё.

![Открыт «Фильтр», выбран метод. Над списком «Скрыто фильтрами» и «Сбросить»](shot:guide-search-filters)

Новый поиск сбрасывает фильтры. В короткую ссылку они не входят.

## Почему запрос с ошибкой

Значок вопроса рядом с фильтрами называется «Как определён статус». Запрос получает статус «Ошибка», если есть хотя бы одно:

- запись уровня WARNING или выше;
- ответ внешней системы HTTP 400 или выше;
- признак ошибки в теле ответа;
- отправка без ответа дольше 30 секунд.

Иначе статус «Успешно». Справочник может решить иначе, он описан на своей странице.

Ответ, который партнёр получил в итоге, в логи не пишется. Поэтому его здесь нет.

## Почему ничего не нашлось

![Сообщение «За 1 час ничего не нашлось» и кнопка «Искать за 24 часа»](shot:guide-search-empty)

Проверьте по порядку:

1. **Значение.** Нет ли опечатки и лишнего символа. Верны ли большие и маленькие буквы.
2. **Несколько значений.** Они должны стоять в одной записи. Оставьте одно.
3. **Период.** Нажмите «Искать за 24 часа». Если случай старше, задайте время через «Свой».
4. **Среда.** Вы могли искать в другой среде. Добавьте её флажком и ищите в обеих.
5. **Срок хранения.** Если записи старше срока, в Threadline их больше нет.
6. **Маска.** По маске телефона поиск не работает.
7. **«Не содержит».** Уберите исключённые значения.

### Сообщение «Запросов с correlation_id нет»

Строки нашлись, но ID запроса в них нет. Собрать их в запрос нельзя, поэтому Threadline сам открывает вкладку «Все записи». Так выглядят, например, служебные строки фоновых задач.

В режиме «Кратко» сообщение называется «Запросов не найдено». Нажмите «Подробно», чтобы увидеть строки.

### Сообщение «Запросов не осталось»

Запросы нашлись, но в каждом есть запись со значением из «Не содержит». Строки без этого значения Threadline показывает во вкладке «Все записи». Чтобы увидеть запросы, уберите значение из «Не содержит».

### Вкладка «Все записи»

Здесь все найденные строки по времени, как в Grafana. Нажмите строку, чтобы раскрыть её. «Показать ещё» подгружает более старые. «К запросу» открывает запрос этой строки.

![Вкладка «Все записи»: строки лога по времени со ссылкой «К запросу»](shot:guide-search-lines)

## Почему поиск может быть неполным

Threadline читает логи частями и не грузит хранилище сверх меры. Если он упёрся в предел, на экране будет сказано об этом.

| Что на экране | Что случилось | Что делать |
|---|---|---|
| «Слишком много запросов» | Нашлось больше 200 запросов. Их записи не загружены. | Сузьте период или добавьте значение. Найденные строки есть во «Все записи». |
| «Показаны не все записи» и «записи неполные» у запроса | Поиск дошёл до предела в 20 000 строк. Запрос прочитан не до конца. При «Не содержит» в непрочитанной части может быть исключённое значение. | Сузьте период. |
| «Поиск остановлен» | Вы нажали «Стоп». Показано найденное до остановки. | Запустите поиск снова. |
| «Подсчёт прервался» или «Записи загружены не все» | Хранилище ответило ошибкой посреди поиска. Найденное осталось на экране. | Нажмите «Повторить». |
| «ответ ещё не пришёл» | Отправка была незадолго до конца периода. Это не ошибка. | Чуть позже нажмите «Обновить». |

Ещё два сообщения не говорят о нехватке данных:

- **«Результат из памяти».** Такой же поиск был меньше минуты назад. «Обновить» ищет заново.
- **«Результат устарел».** Сервер хранит результат 15 минут после последнего обращения. Нажмите «Повторить поиск».

## Пока идёт поиск

Запросы появляются по мере поиска. На экране виден ход: «Подсчёт по часам», затем «Загрузка записей». Кнопка «Стоп» останавливает поиск.

Можно открыть найденный запрос или уйти на другую вкладку: поиск продолжится. Если закрыть вкладку, сервер остановит его примерно через полторы минуты.

Если пропала связь с сервером, вместо хода поиска появится полоса «Не удалось получить состояние поиска». Найденное остаётся на экране. Threadline спрашивает снова сам и, когда связь вернётся, покажет ход и новые запросы.

## Открыть в Grafana

Ссылка «Открыть в Grafana» над списком открывает тот же поиск в новой вкладке. Нужен свой доступ к Grafana.

- Номер карты и телефон в адрес не попадают. Вместо них стоит шаблон, поэтому Grafana может показать больше строк.
- Обычный текст попадает в адрес и в историю браузера.
- В демо-среде, в среде на Loki без Grafana, в режиме «Кратко» и у роли Бизнес ссылки нет.
- В поиске по нескольким средам это меню: в нём пункт на каждую среду.

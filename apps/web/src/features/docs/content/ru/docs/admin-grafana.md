# Подключение хранилища логов

Threadline читает логи проектов из Loki. Без этого шага поиск не заработает. Поддержка VictoriaLogs запланирована, пока её нет.

## Какой способ выбрать

К Loki можно ходить через Grafana или напрямую. Поиск, страницы, подсчёт и проверка подключения работают одинаково, разница только в том, куда идёт сервер и как он входит.

| | Через Grafana, `loki-grafana` | Напрямую, `loki` |
|---|---|---|
| Куда идут запросы | API Grafana, источник Loki | HTTP API Loki `/loki/api/v1` |
| Вход | токен Grafana с ролью Viewer | без входа, токен Bearer или имя и пароль Basic |
| Несколько арендаторов | как настроен источник в Grafana | поле `tenant`, заголовок `X-Scope-OrgID` |
| Ссылка «Открыть в Grafana» | есть | нет |

Через Grafana удобно, если доступ к Loki открыт только через неё. Напрямую — если Grafana нет или она не нужна Threadline.

## Loki через Grafana

### Шаг 1. Получите токен

Нужен API-ключ Grafana или токен сервисного аккаунта с ролью Viewer. Этого хватает для чтения логов.

Токен попадает только на сервер Threadline. В браузер он не передаётся и в журнал не пишется.

### Шаг 2. Задайте адрес и токен

Адрес положите в ConfigMap `threadline-config`, токен в Secret `threadline-secrets`:

```yaml
# ConfigMap
THREADLINE_GRAFANA_URL: https://grafana.corp.example

# Secret
THREADLINE_GRAFANA_TOKEN: <токен>
```

Без любого из этих значений сервер не запустится и назовёт, чего не хватает.

Описание хранилища уже есть в файле настроек в образе:

```yaml
backends:
  grafana:
    type: loki-grafana
    datasource: { name: Loki }
    tokenEnv: THREADLINE_GRAFANA_TOKEN
```

Если источник Loki в вашей Grafana называется иначе, задайте его имя в `THREADLINE_GRAFANA_DATASOURCE`.

### Шаг 3. Перезапустите сервер

```bash
kubectl rollout restart deployment/threadline
kubectl rollout status deployment/threadline
```

## Loki напрямую

### Шаг 1. Опишите хранилище

В файле настроек в образе описано хранилище через Grafana. Для Loki напрямую сохраните свой файл с хранилищем `loki` и смонтируйте его поверх файла в образе, как на странице «Вход через OIDC», шаг 5. Среды проекта ссылаются на это хранилище в поле `backend`.

```yaml
backends:
  loki:
    type: loki
    tokenEnv: THREADLINE_LOKI_TOKEN   # только если Loki за прокси с проверкой токена
```

Адрес берётся из переменной на шаге 2, его можно записать и в файл полем `url`. Адрес указывается без `/loki/api/v1`: этот путь Threadline добавляет сам. Подойдёт и адрес за обратным прокси с подпутём, например `https://logs.corp.example/loki-gateway`.

Как входить, зависит от Loki:

| Loki | Что задать в файле |
|---|---|
| без входа, один арендатор | ничего |
| несколько арендаторов (`auth_enabled: true`) | `tenant: <арендатор>`, несколько через `\|` |
| за прокси с токеном | `tokenEnv: <имя переменной>` |
| за прокси с именем и паролем, например облачный Loki | `usernameEnv` и `passwordEnv`, обе вместе |

Сами токен, имя и пароль в файл не пишутся: сервер с ними не запустится. В файле только имена переменных.

### Шаг 2. Задайте адрес и учётные данные

```yaml
# ConfigMap
THREADLINE_LOKI_URL: http://loki.corp.example:3100
THREADLINE_LOKI_TENANT: team-a   # если у Loki несколько арендаторов

# Secret, только для Loki со входом
THREADLINE_LOKI_TOKEN: <токен>
```

Без адреса сервер не запустится и назовёт `THREADLINE_LOKI_URL`. Если переменная из `tokenEnv`, `usernameEnv` или `passwordEnv` не задана, среды хранилища получат «Не настроено» с её именем.

### Шаг 3. Перезапустите сервер

```bash
kubectl rollout restart deployment/threadline
kubectl rollout status deployment/threadline
```

## Сертификат и прокси

Это общее для обоих способов.

Если сертификат Grafana или Loki выпущен внутренним центром сертификации, смонтируйте корневой сертификат файлом и укажите путь в `THREADLINE_CA_FILE`. Отключить проверку сертификата нельзя.

Если хранилище доступно только через прокси, задайте `HTTPS_PROXY` и `NO_PROXY`.

## Как проверить

1. Запустите проверку подключения. Она не читает сами записи.

   ```bash
   kubectl exec deployment/threadline -- node --disable-warning=ExperimentalWarning apps/server/src/cli/check.ts --env prod
   ```

   Вы увидите строку `Подключение: подключено` и список меток за последние 5 минут. Если что-то не так, команда назовёт причину и выйдет с кодом `1`.

2. Откройте меню профиля справа в шапке и выберите «Настройки сервиса». Нажмите «Проверить» у хранилища. Оно станет «Работает».

3. Найдите что-нибудь за последний час на странице среды. Появится список запросов.

## Если что-то не так

| Что видно | Что это значит | Что сделать |
|---|---|---|
| Сервер не запускается и называет `THREADLINE_GRAFANA_URL`, `THREADLINE_GRAFANA_TOKEN` или `THREADLINE_LOKI_URL` | переменная не задана | задайте её и перезапустите сервер |
| Токен недействителен | хранилище ответило 401 | Grafana: выпустите новый токен. Loki: проверьте токен или имя и пароль; Loki с несколькими арендаторами без `tenant` отвечает 401 `no org id` |
| Нет прав | хранилище ответило 403 или вернуло страницу вместо ответа | проверьте права и адрес |
| Источник не найден | в Grafana нет такого источника или по адресу нет API Loki | Grafana: проверьте `THREADLINE_GRAFANA_DATASOURCE`. Loki: проверьте адрес, он без `/loki/api/v1` |
| Нет связи с хранилищем | адрес не разрешается или соединение отклонено | проверьте адрес, сеть и прокси |
| Сертификат не доверен | сервер не знает, кто подписал сертификат | укажите свой корневой сертификат |
| Хранилище перегружено | Grafana или Loki ответили 429 или 503 | подождите и повторите, Threadline сам не повторяет |
| Threadline занят | все места заняты, очередь не освободилась за 10 секунд | повторите через несколько секунд |

Если хранилище не отвечает, сервис не падает. Проверка готовности его не касается: страницы и справочник работают, а поиск показывает причину.

## Настройки, которые могут понадобиться

Все они необязательны. Часть задаётся переменными.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `THREADLINE_GRAFANA_MAX_CONCURRENT`, `THREADLINE_LOKI_MAX_CONCURRENT` | `4` | сколько запросов идут к хранилищу одновременно |
| `THREADLINE_GRAFANA_TIMEOUT_SECONDS`, `THREADLINE_LOKI_TIMEOUT_SECONDS` | `30` | сколько ждать ответа на один запрос |
| `THREADLINE_GRAFANA_PUBLIC_URL` | адрес Grafana | адрес для браузера, если сервер ходит к ней по другому |
| `THREADLINE_LOKI_TENANT` | | арендатор Loki для заголовка `X-Scope-OrgID` |

Остальные лежат только в файле настроек, в описании хранилища:

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `queueTimeoutSeconds` | 60 | сколько запрос ждёт в очереди |
| `exploreLink` | `true` | только у Grafana: `false` убирает ссылку «Открыть в Grafana» |
| `formScope` | | какие значения меток могут выбирать на странице проекта |

Чтобы поменять поле в файле, смонтируйте свой файл поверх `/app/config/threadline.yaml`. Как это сделать, сказано на странице «Вход через OIDC», шаг 5.

## Какие логи относятся к среде

Среда говорит, какие логи к ней относятся. Логи отбираются по меткам в поле `selector`. Для демо-проекта Demo Pay среды уже описаны в файле настроек, например так:

```yaml
projects:
  pay:
    name: Demo Pay
    environments:
      prod:
        name: Prod
        backend: grafana
        selector:
          - { label: namespace, op: '=', value: pay }
```

Хотя бы одно условие должно быть со знаком `=` и непустым значением. Так сервис не выйдет за логи проекта.

Новые условия задаются на странице проекта. Токен хранилища читает весь Loki, поэтому такие условия сохраняются только в пределах `formScope`. В файле настроек граница задана так:

```yaml
formScope:
  label: namespace
  values: [pay, pay-test, 'pay-pr-*']
```

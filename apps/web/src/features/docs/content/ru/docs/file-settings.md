# Настройки: раздел settings

Раздел `settings` описывает сам проект: название, часовой пояс, срок хранения логов, среды и вид страниц. Стоит сразу после `project`.

Раздел необязателен. Нет раздела: настройки не меняются, и права на них не проверяются. Если задача только в методах и ошибках, не пишите его вовсе.

Менять раздел могут Аналитик и Администратор. Разработчик может оставить его в тексте как есть: раздел, который совпал с базой, правкой не считается.

## Пример

```yaml full
version: 1
project: acme
settings:
  name: Acme Pay
  timezone: Europe/Berlin
  retentionDays: 30
  format: json
  environments:
    - id: prod
      name: Прод
      backend: grafana
      selector:
        - { label: namespace, op: '=', value: acme }
        - { label: container, op: '!=', value: debug, searchOnly: true }
    - id: stands
      name: Стенды PR
      kind: pr-stands
      backend: grafana
      stand: { label: namespace, template: 'acme-pr-{number}' }
```

Если раздел есть, в нём обязательны `name`, `timezone`, `retentionDays`, `format` и `environments`. Поле `view` необязательно.

## Поля проекта

| Поле | Что писать | Где видно |
|---|---|---|
| `name` | Название проекта, до 80 символов | Шапка, страница проектов |
| `timezone` | Имя часового пояса, например `Europe/Berlin` | Всё время на страницах проекта |
| `retentionDays` | Срок хранения логов: целое число дней от 1 до 400 | Поиск не идёт глубже этого срока |
| `format` | Имя формата логов: встроенный `json` или формат из файла настроек | Как Threadline читает записи логов |
| `environments` | Список сред | Выбор среды в карточке поиска |
| `view` | Что показывать в режимах «Подробно» и «Кратко» | Список запросов, страница запроса |

Поменяете `name`, и система самого проекта получит то же название, если её имя не правили формой. Трогать её в `systems` не нужно.

## Среды

Среда: отдельное окружение проекта со своими логами, например «Прод» или «Тест».

| Поле | Обязательно | Что писать |
|---|---|---|
| `id` | да | Идентификатор: строчная латиница, цифры, дефис, до 32 символов. Не только цифры. Не `catalog` и не `settings` |
| `name` | да | Название, до 80 символов |
| `kind` | нет | `single`: обычная среда, это значение по умолчанию. `pr-stands`: стенды pull request |
| `backend` | да | Имя хранилища из файла настроек, например `grafana` |
| `selector` | у обычной среды | Условия: какие записи читает среда |
| `stand` | у стендов | Метка и шаблон стенда |

Среду находят по `id`. Менять его нельзя: новый `id` это новая среда, а старая останется.

Убрать среду файлом нельзя. Среда, которой нет в тексте, остаётся и считается в «нет в файле». Убирают её на форме «Среды». Поэтому пустой список `environments: []` проект не меняет.

Порядок сред хранится. Если названные среды идут как в базе, а новые в конце, порядок не меняется.

### Условия среды

Условие говорит, какие записи читать: метка хранилища, сравнение и значение.

| Поле | Что писать |
|---|---|
| `label` | Имя метки: латиница, цифры и `_`. Не с двух подчёркиваний |
| `op` | `'='`, `'!='`, `'=~'` (регулярное выражение, как в Grafana) или `'!~'` (значение не совпадает с выражением: такие записи не читаются), всегда в кавычках. `'!~'`, как и `'!='`, условием равенства не считается |
| `value` | Значение, до 256 символов. У `=`, `=~` и `!~` без пробелов по краям. Выражение `=~` и `!~` сервис проверяет при запуске и при сохранении формы: незакрытая скобка, просмотр вперёд или обратная ссылка не принимаются |
| `searchOnly` | `true` только у `!=`: исключение действует в обычном поиске, поиск операции его не применяет |

У обычной среды обязательно хотя бы одно условие `=` с непустым значением. Без него среда читала бы логи за пределами проекта. Всего в среде до 20 условий.

Два разных `=` на одну метку дают ошибку: такая среда всегда пуста.

### Граница хранилища

Администратор задаёт в файле настроек, какие значения метки можно читать из этого хранилища. Это настройка `formScope`.

```yaml part
# Это файл настроек threadline.yaml, а не файл проекта
backends:
  grafana:
    formScope: { label: namespace, values: [acme, 'acme-*'] }
```

С такой границей условие `namespace = acme` или `namespace = acme-test` пройдёт, а `namespace = billing` нет. Ошибка назовёт разрешённые значения.

Условия, которые совпали с файлом настроек, граница не проверяет. Хранилище-имитация границы не имеет.

### Стенды

Стенд: временная среда для одного pull request. Значение метки собирается из шаблона и номера стенда.

```yaml part
- id: stands
  name: Стенды PR
  kind: pr-stands
  backend: grafana
  stand: { label: namespace, template: 'acme-pr-{number}' }
```

В шаблоне ровно одно место `{number}` и хотя бы один постоянный символ. Допустимы латинские буквы, цифры, точка, дефис и подчёркивание. Шаблон должен укладываться в границу: для `acme-pr-{number}` в ней нужно значение с звёздочкой, например `acme-*`.

У обычной среды поля `stand` быть не может.

## Вид страниц

Поле `view` задаёт то же, что вкладка «Вид» на форме. Если поля нет, настройка не меняется.

Самый простой способ: возьмите блок `view` из выгрузки и поменяйте нужные значения. Писать его нужно целиком: неполный блок даёт ошибки.

```yaml part
view:
  defaultMode: full
  defaultTab: scheme
  bodyView: pretty
  columns:
    time: { full: true, brief: true }
    request: { full: true, brief: true }
    outcome: { full: true, brief: true }
    component: { full: true, brief: false }
    duration: { full: true, brief: true }
    records: { full: true, brief: false }
    cid: { full: true, brief: false }
  tabs:
    scheme: { full: true, brief: true }
    records: { full: true, brief: false }
  blocks:
    request: { full: true, brief: true }
    response: { full: true, brief: true }
    headers: { full: true, brief: false }
    context: { full: true, brief: false }
    raw: { full: true, brief: false }
    logs: { full: true, brief: false }
```

Здесь показаны встроенные значения. `full` значит показывать в режиме «Подробно», `brief` в режиме «Кратко».

| Поле | Значения | Что задаёт |
|---|---|---|
| `defaultMode` | `full`, `brief` | Режим у тех, кто в этом браузере ещё не выбирал его сам |
| `defaultTab` | `scheme`, `timeline`, `records` | Вкладка при открытии запроса: «Схема», «Шкала времени», «Записи» |
| `bodyView` | `pretty`, `raw` | Вид тел: «Отформатированный» или «Как в логе» |

| Группа | Что внутри |
|---|---|
| `columns` | Колонки списка запросов: `time` «Время», `request` «Запрос», `outcome` «Итог», `component` «Компонент», `duration` «Длительность», `records` «Записей», `cid` «ID запроса» |
| `tabs` | Вкладки запроса: `scheme` «Схема», `records` «Записи». «Шкала времени» есть всегда, её здесь нет |
| `blocks` | Блоки панели шага: `request` «Запрос», `response` «Ответ», `headers` «Заголовки», `context` «Контекст», `raw` «Сырые записи», `logs` «Логи» |

Что нельзя:

- Выключить колонки `time`, `request` и `outcome`: без них строку нельзя прочитать.
- Поставить `blocks.raw.full: false`: нераспознанная запись видна только там.
- Поставить в `defaultTab` вкладку, выключенную в обоих режимах.
- Написать `view: null`. Сбросить вид к встроенному можно только кнопкой на форме «Вид».

Настройка вида меняет только экран. Данные от неё не защищены: их защищает маскирование.

## Чего в файле нет и почему

| Чего нет | Где это живёт | Почему не в файле |
|---|---|---|
| Токены и секреты | Переменные окружения сервера | Файл читают и скачивают многие роли |
| `url`, `tokenEnv`, `datasource` | Файл настроек сервера | Адреса хранилищ и доступы задаёт администратор сервера |
| Определения хранилищ `backends` | Файл настроек сервера | То же. В файле только имя в `backend` |
| Описание формата логов `formats` | Файл настроек сервера | В файле только имя в `format` |
| Логотипы | Форма «Основное» | Это двоичные файлы |
| `id` проекта | Поле `project` | Переименовать проект файлом нельзя |
| Метки версии и скрытие проекта | Страница проектов | Скрытие проекта это отдельное действие |
| Удаление среды | Форма «Среды» | Случайно стёртая строка не должна удалять среду |

Такое поле в разделе даёт ошибку `неизвестное поле «token»` с путём к нему. Файл не применяется.

## Как проверяется раздел

Раздел проходит те же проверки, что формы. Файл не может больше форм.

- **Раздел совпал с базой.** Ничего не меняет и правил ввода не проходит. Старое значение из файла настроек не помешает править методы.
- **Раздел изменился.** Те же сообщения, что на форме. Путь начинается с `settings`, например `settings.environments.0.selector.0.value`.
- **Хранилище не вызывается.** Проверка условий идёт без обращения к хранилищу. Проверить, есть ли записи, можно кнопкой «Проверить подключение» на форме.
- **Значения проверяются масками.** Номер карты или другое значение, которое скрыла бы маска, в название не пройдёт.

## Начальный набор

Файл `config/catalog/<проект>.yaml` сервер загружает сам при подключении к базе. Настройки он не меняет: раздел `settings` в нём пропускается, остальное применяется, а в журнале будет предупреждение. Поэтому выгрузку можно положить туда как есть. Начальные настройки даёт только файл настроек.

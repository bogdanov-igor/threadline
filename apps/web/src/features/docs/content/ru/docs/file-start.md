# С чего начать

Файл проекта: один текст, в котором описан весь проект. Формат: YAML или JSON, структура одна и та же.

## Зачем он нужен

Threadline читает логи. В логах есть адреса, HTTP-коды и тела ответов, но нет слов, понятных человеку.

Файл добавляет эти слова:

- этот адрес называется «Списание»;
- этот хост называется «Платёжный шлюз»;
- код 12 значит «Недостаточно средств», и вот что с этим делать;
- этот ответ с HTTP 200 на самом деле ошибка.

Без файла поиск работает, но шаги подписаны хостами и путями, а ошибки показаны как есть. Шаг: одно действие внутри запроса, например вызов внешней системы. Запрос: все записи лога с одним идентификатором запроса.

Правка действует сразу и на старые логи тоже: заново читать логи не нужно.

## Где он живёт

Откройте проект. В боковом меню найдите группу «Настройки» и пункт «Файл проекта». Адрес вида `/acme/settings/file`. Такая же кнопка есть на странице справочника.

На диске файла нет. Страница собирает текст из базы каждый раз, когда вы её открываете. Поэтому комментарии в файле не сохраняются.

Те же данные можно менять формами в разделах «Настройки» и «Справочник». Правка формой сразу видна в файле, а правка файлом сразу видна в формах.

Файл только описывает уже существующий проект. Создать проект файлом нельзя: новый проект заводит Администратор на странице проектов.

## Кто что может

| Роль | Читать и скачивать | Менять справочник | Менять `settings` | Менять `masking` |
|---|---|---|---|---|
| Бизнес | нет | нет | нет | нет |
| Поддержка | да | нет | нет | нет |
| Разработчик | да | да | нет | нет |
| Аналитик | да | да | да | нет |
| Администратор | да | да | да | да |

Справочник: разделы `idTypes`, `systems` и `general`.

Файл, который меняет чужой раздел, не применяется целиком. Ошибка назовёт этот раздел. Раздел, который совпал с базой, правкой не считается: Разработчик может оставить в тексте `settings` и `masking` как есть и менять только методы.

Если в меню профиля написано «Вход выключен», у всех права Администратора.

## Самый маленький рабочий файл

Этот файл настоящий: он проходит проверку. Замените `acme` на идентификатор своего проекта, а хост и пути на свои.

```yaml full
version: 1
project: acme

idTypes:
  - key: payment
    kind: operation
    name: Платёж

systems:
  - key: acme
    kind: project
    name: Acme Pay
    methods:
      - http: POST
        path: /v1/users/{userId}/payments/{paymentId}/confirm
        name: Подтверждение платежа

  - key: pay
    name: Платёжный шлюз
    hosts:
      - gateway.pay.example:8443
    methods:
      - http: POST
        path: /api/charge
        name: Списание
    errors:
      - code: '12'
        title: Недостаточно средств
        action: Предложите клиенту другую карту
```

Так этот файл выглядит на странице запроса. Шлюз ответил HTTP 200, а в теле ответа ошибка с кодом 12.

![Страница запроса с названиями из файла: запрос «Подтверждение платежа», красный шаг «Платёжный шлюз · Списание», текст «Недостаточно средств» и «Что делать»](shot:file-start-request)

Что откуда взялось:

| Строка файла | Что на экране |
|---|---|
| `name: Подтверждение платежа` | Название запроса в его шапке, на схеме и в списке запросов вместо длинного пути |
| `name: Платёжный шлюз` | Имя системы на схеме и в причине ошибки вместо хоста |
| `hosts` | По этому хосту Threadline понял, что вызов идёт в шлюз |
| `name: Списание` | Название шага рядом с именем системы |
| `code: '12'` | По этому коду Threadline нашёл правило ошибки |
| `title` | Текст ошибки вместо исходного `Insufficient funds on account` |
| `action` | Строка «Что делать» в панели шага |
| `{paymentId}` и тип `payment` | Кнопка «Открыть операцию» и строка «Платёж» с id в шапке запроса |

## Из чего состоит файл

Обязательны только две строки: `version: 1` и `project`. Файл из этих двух строк верен и ничего не меняет.

Остальные разделы необязательны. Раздела нет: то, что он описывает, не меняется.

![Разделы файла слева и места на экране, где они видны, справа](diagram:file-sections)

| Раздел | Что описывает | Подробно |
|---|---|---|
| `settings` | Название проекта, часовой пояс, срок хранения, среды, вид страниц | «Настройки» |
| `idTypes` | Типы идентификаторов: клиент, платёж, перевод | «Id и операции» |
| `systems` | Ваш проект и внешние системы, у каждой свои методы и правила | «Системы» |
| `systems[].methods` | Названия адресов | «Методы» |
| `systems[].errors` | Понятные тексты ошибок | «Ошибки» |
| `systems[].outcomes` | Чем считать ответ: успехом или ошибкой | «Правила итога» |
| `general` | Ошибки и правила итога на весь проект | «Ошибки» |
| `masking` | Какие данные скрывать звёздочками | «Маскирование» |

## Пять правил, которые стоит запомнить

1. **Убрать запись из текста не значит удалить её.** Запись останется и снова появится в файле. Чтобы запись перестала действовать, поставьте ей `hidden: true`.
2. **Убрать поле из записи значит стереть это поле.** Запись заменяется целиком: стёрли строку `hosts`, и у системы больше нет хостов.
3. **Файл применяется целиком или никак.** Одна ошибка в любой строке, и не меняется ничего.
4. **Сначала проверка, потом кнопка.** Страница проверяет текст сама и показывает отчёт. В проект текст попадает только по кнопке «Применить».
5. **Настоящих значений в файле нет.** Ни номеров карт, ни телефонов, ни токенов, ни живых id. Проверка отклонит такой текст.

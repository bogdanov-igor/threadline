# What Business sees and what to do

**For:** Business.

**Task:** understand what happened with a client's request, and pass it on if it is not clear.

1. Paste a value from the support case and click “Find”. You see the status, time, name, outcome and duration. There are no addresses or codes here: this is by design.

   ![The request list in the Business view](shot:learn-business-results)

2. Open the request. The status and name are at the top. Below are the steps in order: which passed, which failed and how long it took. If the error is described, the red block says what happened and what to do.

   ![Request page: a described error, “What to do” and steps in order](shot:learn-business-described)

3. If it says “This error is not described yet: pass the link to support”, click “Share” next to this line. The support contact is there too, if it is set. If a system did not respond, the block names the system and the step that waited for a response, and the request to pass the link is the same.

   ![Red block: which step failed, the “This error is not described yet” line and the “Share” button](shot:learn-business-undescribed)

4. Choose “Short link” and send it to support. Support sees the details and describes the error.

   ![The “Share” menu: “Short link” and “Text for a ticket”](shot:learn-business-share)

## What you should get

You know how the request ended. If the reason is not clear, support already has the link.

In Threadline you have no personal data, request bodies, addresses, codes, IDs or “Detailed” button. The list has only the steps that happened: Threadline does not know about steps the request did not reach. A step with no name in the catalog is labeled with the system name, and a request with no name is called “Unnamed request”. On a short link page everyone has the “Detailed” button. Card numbers are masked there, but the mask does not hide names in free text by default, and addresses and codes are visible there.

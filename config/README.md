# Настройка Threadline

Сервер читает один файл в формате YAML: по умолчанию `config/threadline.yaml`, другой путь задаёт переменная `THREADLINE_CONFIG`. Изменения применяются после перезапуска. То, что отличается по средам, можно задать переменными окружения: они важнее файла, см. [Развёртывание: переменные](#развёртывание-переменные).

При старте сервер проверяет файл целиком. Если есть ошибки, он не запускается и перечисляет их все, у каждой путь к полю. Например:

```
Threadline не запущен: ошибки настройки, файл /…/config/threadline.yaml
  • projects.pay.environments.prod.backend: среда «prod» ссылается на хранилище «graphana», которого нет в backends
```

Секреты в файле не хранятся. Файл называет только имя переменной окружения, а значение лежит в `.env` в корне проекта или в окружении процесса. Если переменная не задана, сервер запускается, а среды этого хранилища получают состояние «не настроено».

## Разделы

| Раздел | Что задаёт |
|---|---|
| `defaults` | проект и среда, которые открываются по умолчанию |
| `backends` | хранилища логов, на них ссылаются среды |
| `projects` | проекты, у каждого часовой пояс и среды |
| `formats` | необязательно: профили формата записей своих проектов |
| `search` | необязательно: пределы поиска |
| `regional` | необязательно: номера телефонов страны и образцы документов в тексте, см. [Региональные правила](#региональные-правила) |
| `extras` | необязательно: дополнения интерфейса, см. [Раздел `extras`](#раздел-extras) |

## Хранилище `loki-grafana`

Loki через API Grafana. Grafana 8.5 проксирует запросы к источнику только по числовому id, а в Grafana 13 такого пути уже нет, есть только путь по uid. Threadline сначала идёт по числовому id, а если Grafana ответила 404, — по uid. Если источник задан именем или uid, Threadline сам узнаёт id и uid запросами, которые доступны роли Viewer.

| Поле | Обязательно | По умолчанию | Что значит |
|---|---|---|---|
| `url` | да | | адрес Grafana, `https://...` |
| `datasource` | нет | `{ name: Loki }` | источник Loki: `{ name: ... }`, `{ uid: ... }` или `{ id: ... }` |
| `tokenEnv` | да | | имя переменной окружения с токеном Grafana (API-ключ или токен сервисного аккаунта) |
| `publicUrl` | нет | `url` | адрес Grafana, который открывается у пользователя, если сервер ходит к ней по другому. Без учётных данных, параметров и фрагмента |
| `exploreLink` | нет | `true` | `false` убирает ссылку «Открыть в Grafana» у всех сред этого хранилища |
| `caFile` | нет | | свой корневой сертификат в PEM, путь от файла настроек. Проверку сертификата отключить нельзя |
| `maxConcurrent` | нет | 4 | сколько запросов к хранилищу идут одновременно, остальные ждут. Поиск операции занимает на одно место меньше: одно остаётся другим пользователям |
| `queueTimeoutSeconds` | нет | 60 | сколько запрос ждёт в очереди, потом «Threadline занят» |
| `timeoutSeconds` | нет | 30 | тайм-аут одного запроса к хранилищу |
| `formScope` | нет | | какие значения метки форма проекта вправе читать из этого хранилища, см. [Проекты на страницах](#проекты-на-страницах) |

### Ссылка «Открыть в Grafana»

В результатах поиска и на странице запроса есть ссылка в Explore с тем же селектором, периодом и фильтром. Её строит сервер без обращения к Grafana, токена в адресе нет.

```yaml
auth: off
defaults: { project: pay, environment: prod }
backends:
  grafana:
    type: loki-grafana
    url: http://grafana.corp.example:3000
    publicUrl: https://grafana.corp.example
    datasource: { name: Loki }
    tokenEnv: THREADLINE_GRAFANA_TOKEN
projects:
  pay:
    name: Demo Pay
    environments:
      prod:
        name: Prod
        backend: grafana
        selector:
          - { label: namespace, op: '=', value: pay }
```

- **Источник.** В ссылку идёт имя или uid из `datasource`. С числовым `{ id: ... }` ссылки нет: Explore его не понимает, а спрашивать имя у Grafana ради ссылки сервис не будет. Если имя неверное, Grafana молча откроет источник по умолчанию.
- **Адрес.** Без `publicUrl` ссылка ведёт на `url`. Если в `url` есть имя пользователя и пароль, а `publicUrl` не задан, логи читаются, а ссылки нет. Те же значения в `publicUrl` останавливают запуск.
- **Права.** У пользователя должна быть своя учётная запись Grafana с доступом к Explore: роль Editor или настройка `viewers_can_edit`. Токен сервиса для этого не используется. Если доступа нет ни у кого в среде, поставьте `exploreLink: false`.
- **Значения.** Полного номера карты, телефона, личного номера и паспорта в адресе нет: вместо них шаблон из той части значения, которую показывает маска, поэтому Grafana может показать больше строк. Значение, в котором такой номер не отделить, закрывает ссылку. Остальной текст, например фамилия, попадает в адрес и историю браузера как введён, об этом предупреждает подсказка кнопки.

## Хранилище `loki`

Loki напрямую, без Grafana: HTTP API `/loki/api/v1` (`query_range` для строк, `query` для подсчёта, `labels` и `label/<имя>/values` для проверки подключения и списка стендов). Подходит для Loki без Grafana и для Loki рядом с Grafana любой версии. Всё, что выше хранилища, работает так же, как у `loki-grafana`: очередь и пределы, чтение страницами, подсчёт, поиск операции, проверка подключения.

| Поле | Обязательно | По умолчанию | Что значит |
|---|---|---|---|
| `url` | да | | адрес Loki без `/loki/api/v1`, например `http://loki:3100` или адрес за обратным прокси с подпутём. Без имени, пароля, параметров и фрагмента |
| `tenant` | нет | | арендатор для заголовка `X-Scope-OrgID`, если у Loki несколько арендаторов (`auth_enabled: true`). Несколько арендаторов через `\|`, если Loki разрешает запросы по нескольким. Без поля заголовка нет |
| `tokenEnv` | нет | | имя переменной окружения с токеном Bearer: Loki за прокси с проверкой токена |
| `usernameEnv`, `passwordEnv` | нет | | имена переменных окружения с именем и паролем входа Basic, обе вместе. С `tokenEnv` не задаются |
| `caFile` | нет | | корневой сертификат в PEM, путь от файла настроек. Проверку сертификата отключить нельзя |
| `maxConcurrent`, `queueTimeoutSeconds`, `timeoutSeconds` | нет | 4, 60, 30 | как у `loki-grafana` |
| `formScope` | нет | | как у `loki-grafana`, см. [Проекты на страницах](#проекты-на-страницах) |

```yaml
backends:
  # Loki без входа, один арендатор
  loki:
    type: loki
    url: http://loki:3100
  # Loki с несколькими арендаторами за прокси с входом Basic, например облачный Loki
  logs:
    type: loki
    url: https://logs.corp.example
    tenant: team-a
    usernameEnv: THREADLINE_LOKI_USERNAME
    passwordEnv: THREADLINE_LOKI_PASSWORD
```

- **Учётные данные.** Только переменными окружения: токен, имя и пароль в файле останавливают запуск, значение в сообщение не попадает. Без входа переменные не нужны. Если переменная из `tokenEnv`, `usernameEnv` или `passwordEnv` не задана, среды хранилища получают «не настроено» с именем переменной, а строгий запуск в образе не стартует.
- **Арендатор.** Loki с несколькими арендаторами без заголовка отвечает 401 `no org id`: проверка подключения подскажет задать `tenant`.
- **Прокси и сертификат.** Как у `loki-grafana`: `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `caFile` или `THREADLINE_CA_FILE`.
- **Ошибки.** Те же состояния, что у `loki-grafana`: 401 — учётные данные не приняты, 403 — нет прав, 404 — по адресу нет API Loki, 429 и 503 — Loki просит подождать, лимит Loki, тайм-аут, ответ больше 50 МБ. Тексты называют Loki и поле `url`.
- **Ссылка «Открыть в Grafana».** У сред хранилища `loki` её нет: у Loki нет своего интерфейса запросов.
- **Переменные.** Адрес, арендатор и пределы единственного хранилища `loki` можно задать переменными `THREADLINE_LOKI_*`, см. [Развёртывание: переменные](#развёртывание-переменные).

## Хранилище `mock`

Синтетические записи в формате настоящих. Наружу не ходит, токен не нужен.

| Поле | По умолчанию | Что значит |
|---|---|---|
| `dataset` | `pay` | набор записей: синтетические записи демо-проекта Demo Pay во встроенном формате `json` |
| `latencyMs` | 0 | задержка каждого ответа |
| `fail` | | имитировать ошибку: `unauthorized`, `forbidden`, `not-found`, `network`, `certificate`, `timeout`, `overloaded`, `limit`, `bad-response` |

Поля `maxConcurrent`, `queueTimeoutSeconds`, `timeoutSeconds` работают так же, как у `loki-grafana`.

## Проект

| Поле | По умолчанию | Что значит |
|---|---|---|
| `name` | | название в интерфейсе |
| `logo` | | необязательно: логотип в шапке, см. ниже |
| `timezone` | `UTC` | часовой пояс, в котором интерфейс показывает время |
| `format` | `json` | профиль формата записей: встроенный `json` или имя профиля из `formats` (см. «Формат записей») |
| `retentionDays` | 30 | срок хранения логов: раньше него свой период поиска не начинается |

### Логотип проекта

```yaml
projects:
  acme:
    name: Acme
    logo:
      light: logos/acme-light.svg
      dark: logos/acme-dark.svg # необязательно: без неё в обеих темах показывается light
    environments:
      demo:
        name: Демо
        backend: demo
        selector:
          - { label: namespace, op: '=', value: acme }
```

- **Где лежит файл.** В папке файла настроек, путь считается от неё. Сегменты из латинских букв, цифр, точки, дефиса и подчёркивания. Адрес `https://`, абсолютный путь и выход за папку останавливают запуск сервера.
- **Формат.** PNG и SVG, не больше 256 КБ на файл. В SVG нужны `viewBox` или числовые `width` и `height`, скрипты, внешние ссылки и встроенные картинки не принимаются.
- **Размер.** В шапке высота 20px при окне до 1024px и 22px шире, ширина по пропорции файла, но не больше 80px и 120px. Лучше всего квадрат или пропорция до 4:1. Для PNG берите файл не ниже 66px.
- **Если файл не подошёл.** Сервер запускается и пишет в журнал поле и причину, `threadline:check` печатает то же. Проект показывается с одним названием. Если не подошла хотя бы одна из двух версий, логотипа нет в обеих темах.
- **Смена файла.** Файл читается один раз при старте: новый логотип появится после перезапуска сервера.

Логотип Demo Pay в `config/logos/` это сгенерированная заглушка. Свой файл заменяет её без правок кода: положите файлы в `config/logos/`, при другом имени или формате поправьте пути в `logo` и перезапустите сервер.

## Поиск

Секция `search` необязательна, все поля имеют значения по умолчанию.

| Поле | По умолчанию | Что значит |
|---|---|---|
| `countChunkMinutes` | 60 | первый проход считает записи кусками этой длины, от свежих к старым: так каждый запрос к Loki укладывается в тайм-аут |
| `maxRequests` | 200 | если первый проход нашёл больше запросов, второй проход не выполняется, а пользователь видит просьбу сузить поиск |
| `batchSize` | 50 | сколько correlation_id забирается одним запросом второго прохода |
| `maxLinesPerQuery` | 5000 | строк в одной странице запроса к хранилищу (не больше лимита Loki `max_entries_limit_per_query`) |
| `maxLinesPerSearch` | 20000 | предел строк на один поиск, дальше показываются не все записи |
| `periodMarginMinutes` | 5 | на сколько расширять период второго прохода, чтобы запросы на границе пришли целиком |

## Региональные правила

Раздел `regional` необязателен. Без него правила международные:

- телефон — номер с `+` и кодом страны, от 8 до 15 цифр (`+44 7700 900123`). Цифры без плюса телефоном не считаются ни в поиске, ни в маске текста;
- номер карты — 12–19 цифр с проверкой Луна, счёт — IBAN с верным контрольным числом и номер после `account/` или `accounts/` в адресе;
- личный номер и паспорт — только по именам полей (`national_id`, `tax_id`, `ssn`, `passport_number`…). Свои имена проекта добавляются полями вида в справочнике.

Раздел добавляет правила одной страны. Он действует на весь сервис: на маску сервера, распознавание значения поиска и маску страницы из лога в браузере. Изменение применяется после перезапуска.

| Поле | Что значит |
|---|---|
| `phone.countryCode` | код страны без плюса, 1–3 цифры |
| `phone.nationalDigits` | цифр в национальном номере без префикса, от 4 до 14 |
| `phone.trunkPrefix` | необязательно: местный префикс перед национальным номером, `0` или `8` |
| `phone.groups` | необязательно: группы национального номера, сумма равна `nationalDigits`. С группами разделитель допустим только между ними, без групп — между любыми цифрами |
| `patterns.<вид>` | до 10 выражений RE2 на вид: `phone`, `national_id`, `passport`, `account_number`. Совпадение в тексте закрывается маской вида. Без именованных групп и с линейным временем, иначе сервер не запустится |

С планом номеров телефон узнаётся и без плюса с кодом страны (`447700900123`), а в поиске ещё и в местной записи: `07700 900123`, `7700 900123`. Девять или десять цифр подряд без кода страны остаются текстом: так они не путаются с id.

Пример демо-проекта (в `config/threadline.yaml`):

```yaml
regional:
  phone: { countryCode: '44', nationalDigits: 10, trunkPrefix: '0' }
  patterns:
    passport: ['[A-Z]{2}\d{7}']
    national_id: ['[A-Z]{2}\d{6}[A-D]']
```

Пример Узбекистана: номера `998`, ПИНФЛ, серия паспорта и счёт из 20 цифр.

```yaml
regional:
  phone: { countryCode: '998', nationalDigits: 9, trunkPrefix: '8', groups: [2, 3, 2, 2] }
  patterns:
    national_id: ['[3-6](?:0[1-9]|[12]\d|3[01])(?:0[1-9]|1[0-2])\d{9}']   # ПИНФЛ
    passport: ['[A-Z]{2}\d{7}']                                            # серия и номер
    account_number: ['\d{20}']                                              # счёт
```

Имена полей своих систем добавляются в разделе `masking` файла справочника проекта:

```yaml
masking:
  - { type: national_id, enabled: true, keys: [pinfl, national_id_number] }
  - { type: phone, enabled: true, keys: [phone_mobile, phone_home] }
```

## Среда

| Поле | Что значит |
|---|---|
| `name` | название в интерфейсе |
| `kind` | `single` (по умолчанию) или `pr-stands` |
| `backend` | идентификатор хранилища из `backends` |
| `selector` | условия на метки потока: `{ label, op, value, searchOnly? }`, `op` — `=`, `!=`, `=~` (регулярное выражение целиком по значению, как в Grafana) или `!~` (значение не совпадает с выражением: такие записи не читаются). `!~`, как и `!=`, условием равенства не считается и границу `formScope` не даёт. `searchOnly: true` у условия `!=` — исключение только для обычного поиска: поиск потоков операции его не применяет, обычный поиск, «Все записи» и страница запроса — применяют. У условия `=` отметка — ошибка при старте |
| `stand` | только для `pr-stands`: `{ label, template }`, шаблон с местом `{number}` |
| `examples` | примеры поиска на стартовой странице среды, до 6: `{ label, values, period? }`. `label` — подпись до 60 символов, строкой на все языки или по языкам интерфейса: `{ ru: …, en: … }` (нет подписи на языке — видна другая), `values` — от 1 до 5 значений по правилам строки поиска, `period` — `15m`, `1h`, `6h` или `24h` (нет поля — 6 ч). Щелчок по примеру заполняет строку поиска и ищет. Значения проверяются по правилам строки поиска, маскирование файла проекта их не проверяет: номер карты на экране под маской, но в браузер и в файл проекта приходит целиком. Пишите только выдуманные или тестовые значения |

У обычной среды в селекторе должно быть хотя бы одно условие `=` с непустым значением: так сервис не выходит за логи проекта. У среды стендов это условие даёт сама метка стенда.

Список живых стендов Threadline берёт из значений метки стенда за последние 7 дней. Номер стенда — от одной до шести цифр.

Идентификаторы проектов, сред и хранилищ: строчные латинские буквы, цифры и дефис, до 32 символов. Идентификаторы среды `catalog` и `settings` заняты адресами `/:project/catalog` и `/:project/settings`.

## Формат записей

Профиль формата говорит Threadline, как превратить строку хранилища в запись: где время, уровень, текст, correlation_id, HTTP-запрос и ответ. Проект ссылается на профиль полем `format`. Встроенный профиль `json` описывает записи JSON по одной на строку, как их пишет приложение; в этом формате пишет демо-проект Demo Pay. Профиль нового проекта пишется в секции `formats`; правок кода он не требует.

```yaml
formats:
  acme:            # имя профиля; json занято встроенным
    component: [container]
    variants: [...]
projects:
  acme:
    name: Acme
    format: acme
```

Секция `formats` проверяется целиком при старте, даже профиль, на который не ссылается ни один проект. Путь в сообщении об ошибке называет вариант по имени: `formats.acme.variants.0(app).fields.time`.

### Поля профиля

| Поле | Обязательно | Что значит |
|---|---|---|
| `component` | нет | метки потока, из которых берётся компонент записи: значение из `gateways`, если оно есть в одной из них, иначе первая непустая |
| `gateways` | нет | значения меток компонента, которые тоже означают шлюз; только вместе с `component` |
| `levels` | нет | дополнение к таблице уровней: имя или число → число по шкале Monolog (0–1000) |
| `layers` | нет | общие слои: `{ name, decode, from?, pattern? }` |
| `variants` | да | варианты записи: `{ name, when?, gateway?, layers?, fields?, kinds?, steps? }` |
| `count` | нет | `{ regexp }` — выражение подсчёта; без него выводится из путей correlationId |

**Слои** раскрывают строку по шагам. Слой без `from` берёт строку хранилища, слой с `from` — поле прежнего слоя. Общие слои строгие: не раскрылся первый — запись «не разобрана», следующий — запись показана текстом. Слои варианта мягкие: нераскрытый слой просто пуст, вариант от этого не отменяется. Декодеры:

| `decode` | Вход | Поля слоя |
|---|---|---|
| `json` | строка с объектом JSON или уже объект | ключи объекта; целые больше 2^53 — строкой исходных цифр |
| `text` | строка до 64 КБ | именованные группы выражения `pattern` |
| `http` | сырое HTTP-сообщение | `method`, `uri`, `status`, `headers`, `body` |

**Варианты** — форматы, которые встречаются в одном потоке. Они проверяются по порядку, запись берёт первый подходящий. Запись без подходящего варианта показывается текстом, ни одна строка не теряется. `gateway: true` — записи варианта — записи шлюза: они открывают запрос, но компонентом запроса не считаются.

**Условия `when`** — все заданные должны выполняться; без `when` вариант или правило подходит всегда:

| Условие | Выполнено, если |
|---|---|
| `labels: { container: app }` | метка потока равна значению или одному из списка; проверяется первым |
| `has: [путь, …]` | каждое поле есть и не null |
| `hasAny: [путь, …]` | хотя бы одно поле есть и не null |
| `missing: [путь, …]` | ни одного поля нет или оно null |
| `equals: { путь: значение }` | поле равно значению или одному из списка, сравнение по тексту |

У варианта со своим слоем в `when` должно быть `has` по полю этого слоя, иначе битая строка станет пустой записью.

**Пути** — `<слой>.<ключ>.<ключ>…`. Ключ с точкой находится сам: `rec.trace.id` берёт и `{"trace.id": …}`, и `{"trace": {"id": …}}`. Сегмент из цифр — индекс массива. В слое `http` путь `req.headers.X-Request-Id` ищет заголовок без учёта регистра и даёт первое значение. Внутрь строки путь не заходит: строку раскрывает только слой. Вместо пути можно дать список: берётся первое значение, которое есть и не null.

**Поля записи** (`fields` варианта и правил вида):

| Поле | Значение |
|---|---|
| `time` | ISO 8601 с поясом или число от эпохи; единица по числу цифр: 10 — секунды, 13 — мс, 16 — мкс, 19 — нс. Время без пояса или неразобранное заменяется временем хранилища |
| `level` | список путей: имя — первая строка не из цифр, число — первое число; недостающее — по таблице. 300 и выше — ошибка |
| `message`, `method`, `uri`, `action` | строка, иное — текст JSON |
| `correlationId`, `requestId` | непустая строка или число |
| `status` | число или строка, которая читается числом |
| `headers`, `payload` | как есть |
| `body` | строка, объект — текст JSON |
| `context` | объект «остальной контекст» без ключей, которые взяты путями других полей варианта |

Таблица уровней: имена Monolog (`DEBUG` 100 … `EMERGENCY` 600), а также `WARN` 300, `ERR` 400, `CRIT` 500, `FATAL` 600. Числовые шкалы других журналов задаёт `levels`, например pino: `levels: { "30": 200, "40": 300, "50": 400, "60": 500 }`.

**Правила вида** (`kinds`) — по порядку: `{ kind, when?, fields? }`, вид — `incoming`, `call`, `send`, `response` или `log`. Первое выполненное правило задаёт вид и заменяет свои поля. Нет правила — `log`.

### Правила шага графа

`steps` варианта отмечают записи-логи, которые граф потока рисует отдельным узлом: обращение к базе (`as: db`) или ожидание (`as: wait`). Правила проверяются по порядку и только у записей вида `log`, первое выполненное даёт подсказку шага. Вид записи, её показ в записях, статус запроса и маскирование не меняются.

```yaml
steps:
  - as: db                                 # db или wait
    when: { equals: { rec.step: db } }
    fields: { durationMs: rec.duration_ms }  # ещё host и title, все необязательны
```

| Поле | Что значит |
|---|---|
| `as` | `db` — база данных, `wait` — ожидание. Другие виды (`cache`, `queue`) — ошибка при старте |
| `when` | условие по правилам вариантов |
| `fields.durationMs` | длительность в мс: число или строка из цифр с точкой, иначе узел без длительности |
| `fields.host`, `fields.title` | хост и подпись узла без технических деталей |

Систему узла базы называет справочник; без него узел подписан «База данных». Обращение дольше 200 мс граф показывает предупреждением. Во встроенном профиле `json` два правила: запись с `"step": "db"` — обращение к базе, с `"step": "wait"` — ожидание, длительность в `duration_ms`.

### Выражение подсчёта

Первый проход поиска считает записи по correlation_id одним регулярным выражением над сырой строкой хранилища, без разбора записи. Выражение — RE2 с ровно одной группой `(?P<cid>…)`. Если `count` не задан, оно выводится из путей correlationId:

- ключ JSON — `"ключ":` на любом уровне экранирования; если у ключа есть родитель внутри слоя, перед ним стоит `"родитель": {…`, где между ними — скаляры и объекты одного уровня вложенности. Ключ после объекта, вложенного глубже, или после строки со скобкой `{` `}` такое выражение не видит: для этого формата задайте `count.regexp` (`threadline:check` покажет такие строки). Значения `null`, `true` и `false` ключом не считаются;
- заголовок слоя `http` — строка заголовка `Имя:` после перевода строки;
- слой `text`, который читает строку хранилища, — его выражение, где группа correlationId становится `cid`.

Явное `count.regexp` нужно, если correlation_id берётся из слоя `text` с `from`, из ключа `id` без родителя, по индексу массива или из нескольких слоёв разных видов. Сервер не запустится и попросит его задать.

Все выражения профиля (слой `text` и подсчёт) — одно подмножество RE2, которое JS выполняет так же: группы `(?P<имя>…)` или `(?<имя>…)`, флаги только ведущей группой `(?i)`, `(?s)`, `(?is)`, без просмотра вперёд и назад и без обратных ссылок. Экранирование — только `\d \w \s \b`, `\n \r \t \f \v`, `\xHH` и знаки препинания: `\p{…}`, `\A`, `\z`, `\Q…\E` и классы POSIX `[[:alpha:]]` JS читает иначе. Класс не начинается с `]` (пишите `\]`), счётчик повтора — не больше 1000.

Слой `text` разбирается на сервере синхронно, поэтому сервер запускается с флагами V8, которые переводят выражение на линейный движок после 1000 возвратов: опечатка вида `(a+)+` не повесит поиск. `(?i)` этому не мешает — в JS он раскрывается в классы `[aA]`. Линейный движок не строит больше 16 копий повтора, и выражение слоя `text` со счётчиком больше 16 (`[0-9a-f]{32}`) или с вложенными счётчиками (`(a{4}){5}`) сервер не примет: пишите `+`. Предел 64 КБ на строку слоя `text` защищает только память.

### Проверка на образце

```
pnpm threadline:check <формат> <файл> [--label container=app ...]
```

Одна строка файла — одна строка хранилища. Команда печатает число строк по вариантам и видам, долю строк с correlation_id, номера строк, где ключ подсчёта не равен разобранному, и поля, путь которых не дал значения ни на одной строке. Значения и тела не печатаются.

### Пример: JSON приложения и строки nginx

```yaml
formats:
  acme:
    component: [container]
    variants:
      - name: app
        when: { labels: { container: app }, has: [rec.ts] }
        layers: [{ name: rec, decode: json }]
        fields:
          time: rec.ts
          level: rec.lvl
          message: rec.msg
          correlationId: rec.trace_id
          requestId: rec.span_id
          method: rec.http.method
          uri: rec.http.url
          status: rec.http.status
          body: rec.http.body
          context: rec.extra
        kinds:
          - { kind: incoming, when: { equals: { rec.msg: incoming request } } }
          - { kind: send, when: { equals: { rec.msg: outgoing request } } }
          - { kind: response, when: { equals: { rec.msg: outgoing response } } }
      - name: nginx
        when: { labels: { container: nginx }, has: [access.status] }
        layers:
          - { name: access, decode: text, pattern: '^(?<ip>\S+) \S+ \S+ \[[^\]]+\] "(?<method>[A-Z]+) (?<uri>\S+)[^"]*" (?<status>\d{3})' }
        fields: { message: access.uri, method: access.method, uri: access.uri, status: access.status }
    # count не задан: выводится из rec.trace_id
```

### Встроенный формат json

Встроенный профиль `json` — значение `format` по умолчанию. Он читает записи JSON по одной на строку, как их пишет приложение в stdout, без обёртки сборщика логов. Если сборщик заворачивает строку в свой JSON, опишите свой профиль со слоем обёртки (пример выше). Запись приложения:

| Поле | Что значит |
|---|---|
| `time` | время: ISO 8601 с поясом или число от эпохи. Подходят и `timestamp`, `@timestamp`, `ts` |
| `level` | уровень именем (`debug`, `info`, `notice`, `warning`, `error`) или числом по шкале Monolog. Подходит и `severity` |
| `msg` | текст записи. Подходит и `message`: запись без них — не запись приложения |
| `correlation_id` | correlation_id запроса. Пишется на верхнем уровне записи до вложенных объектов: выражение подсчёта берёт первый такой ключ строки |
| `request_id` | id обмена: связывает отправку и ответ, а у шлюза — вход и вызов сервиса |
| `request` | вход запроса в сервис: `{ method, path, headers, body }`. Запись с `request` — вид `incoming` |
| `upstream` | вызов другой системы: `{ method, url, headers, body }` — отправка (`send`), со `status` — ответ (`response`) |
| `action`, `payload` | вызов по имени до отправки (действие SOAP, метод RPC) и его параметры: вид `call` |
| `step`, `duration_ms` | шаг графа: `db` — обращение к базе, `wait` — ожидание; длительность в мс |
| `ctx` | остальной контекст: показывается блоком «Контекст» |

Запись шлюза — `raw_request` с сырым HTTP входящего запроса. Её вид `incoming`, correlation_id берётся из заголовка `X-Correlation-Id`, `request_id` — из `X-Request-Id`. Строка не JSON (стек, строка доступа `[GIN]`) показывается текстом; шлюзом её делает метка компонента `gateway`.

Примеры строк хранилища, по одной на вид:

```
{"time":"2026-11-12T09:15:30.123456Z","level":"debug","msg":"request received","raw_request":"POST /v1/users/u1/payments HTTP/1.1\r\nHost: api.pay.example\r\nX-Correlation-Id: 5b0c1d2e-3f40-4a51-8b62-7c83d94ea5f6\r\nX-Request-Id: a1b2c3d4-e5f6-4a07-9b18-c29d3e4f5a60\r\n\r\n{\"amount\":700000}"}
{"time":"2026-11-12T09:15:30.130001Z","level":"info","msg":"incoming request","correlation_id":"6300014100001","request_id":"6300014100001","request":{"method":"POST","path":"/v1/cards/lookup","body":"{\"card_tokens\":[\"400000ABCDEF1234\"]}"}}
{"time":"2026-11-12T09:15:30.131205Z","level":"info","msg":"processor call","correlation_id":"6300014100001","request_id":"6300014100001","action":"getCard","payload":[{"CARD":"400000ABCDEF1234"}]}
{"time":"2026-11-12T09:15:30.134512Z","level":"info","msg":"http request sending","correlation_id":"6300014100001","request_id":"6300014100001","upstream":{"method":"POST","url":"https://processor.pay.example:8443/soap/issuing","headers":{"Content-Type":["text/xml"]},"body":"<soap/>"}}
{"time":"2026-11-12T09:15:30.402277Z","level":"info","msg":"http response received","correlation_id":"6300014100001","request_id":"6300014100001","upstream":{"method":"POST","url":"https://processor.pay.example:8443/soap/issuing","status":200,"body":"<soap/>"}}
{"time":"2026-11-12T09:15:30.140117Z","level":"info","msg":"db query","correlation_id":"6300014100001","step":"db","duration_ms":12,"ctx":{"host":"db.pay.example","port":"5432"}}
```

**Подсчёт.** Выражение берёт первый ключ `"correlation_id":"` без экранирования — верхний уровень записи — или заголовок `X-Correlation-Id` сразу после экранированного `\r\n` в сыром HTTP шлюза. Тот же ключ в строке тела экранирован и не подходит. Запрос шлюза с переводами строк LF подсчёт не находит.

**Вход GET в поиске операции.** Опросы партнёра узнаются по объекту `request` с `"method": "GET"` (метод — до вложенных объектов `request`) или по `raw_request`, который начинается с `GET `.

Так выглядит встроенный профиль; в файле его писать не нужно. Он же — образец для нового проекта.

```yaml
formats:
  json:
    component: [container, app_kubernetes_io_component]
    gateways: [gateway]
    variants:                           # общих слоёв нет: строка не JSON проходит мимо вариантов и остаётся текстом
      - name: app
        when: { hasAny: [rec.msg, rec.message], missing: [rec.raw_request] }
        layers: [{ name: rec, decode: json }]
        fields:
          time: [rec.time, rec.timestamp, 'rec.@timestamp', rec.ts]
          level: [rec.level, rec.severity]
          message: [rec.msg, rec.message]
          correlationId: rec.correlation_id
          requestId: rec.request_id
          method: rec.upstream.method
          uri: rec.upstream.url
          status: rec.upstream.status
          headers: rec.upstream.headers
          body: rec.upstream.body
          payload: rec.payload
          action: rec.action
          context: rec.ctx
        kinds:
          - kind: incoming
            when: { has: [rec.request] }
            fields: { method: rec.request.method, uri: rec.request.path, headers: rec.request.headers, body: rec.request.body }
          - { kind: call, when: { has: [rec.action], missing: [rec.upstream] } }
          - { kind: send, when: { has: [rec.upstream.url], missing: [rec.upstream.status] } }
          - { kind: response, when: { has: [rec.upstream.url, rec.upstream.status] } }
        steps:                          # подсказка шага графа; хоста базы в записи нет, систему называет справочник
          - { as: db, when: { equals: { rec.step: db } }, fields: { durationMs: rec.duration_ms } }
          - { as: wait, when: { equals: { rec.step: wait } }, fields: { durationMs: rec.duration_ms } }
      - name: gateway
        when: { has: [rec.raw_request] }
        gateway: true                   # записи шлюза открывают запрос, но компонентом запроса не считаются
        layers:                         # слои варианта, мягкие
          - { name: rec, decode: json }
          - { name: req, decode: http, from: rec.raw_request }
        fields:
          time: [rec.time, rec.timestamp, 'rec.@timestamp', rec.ts]
          level: [rec.level, rec.severity]
          message: [rec.msg, rec.message]
        kinds:
          - kind: incoming
            when: { has: [req.method] }
            fields:
              correlationId: req.headers.X-Correlation-Id
              requestId: req.headers.X-Request-Id
              method: req.method
              uri: req.uri
              headers: req.headers
              body: req.body
    count:
      # Первый ключ correlation_id верхнего уровня или заголовок X-Correlation-Id после экранированного CRLF у шлюза.
      regexp: '(?i)(?:"correlation_id":\s*"|\\r\\nX-Correlation-Id:\s*)(?P<cid>[0-9a-z._:-]+)'
```

## Выборка живых записей

Разовая команда: читает немного настоящих записей и пишет файл с их устройством, без значений. Сервер и интерфейс её не используют. Настройку читает только из этого файла: проект со страницы проектов для неё неизвестен.

```bash
pnpm threadline:sample --env <среда> --kind <labels|background|names|all> [--project <проект>] [--since 6h] [--out <каталог>] [--live]
pnpm threadline:sample --clean [--out <каталог>]
```

| Вид | Что читает | Что идёт в файл |
|---|---|---|
| `labels` | имена меток, значения `container`, `app_kubernetes_io_component`, `app_kubernetes_io_sub_service`, строки шлюза за час | имена и значения меток, группы меток потока шлюза; содержимое строк шлюза не идёт |
| `background` | значения тех же меток, строки кандидатов (worker, consumer, cron, job, queue, scheduler), поток по correlation_id | есть ли correlation_id, паузы, число сегментов, устройство записи |
| `names` | две порции строк с адресом и порция с `ERROR` | сводка по справочнику, до 2 записей на группу, список неизвестного до 50 строк |

**Пределы.** Заданы в коде, настройкой не меняются:

- не больше 13 запросов за запуск и один запрос id источника, строго по одному, через защитный слой хранилища;
- не больше 1000 строк, окно запроса не больше 24 часов, не больше 120 секунд на запуск;
- повторов нет: первая ошибка хранилища останавливает запуск.

`--since` принимает значения от `1m` до `24h`, по умолчанию `6h`, и действует на значения меток и `background`. Среда стендов PR отклоняется.

**Коды выхода.**

| Код | Значение |
|---|---|
| 0 | всё выполнено, пустой результат тоже |
| 1 | хранилище вернуло ошибку или исчерпан предел; уже собранное записано с пометкой `stopped`. Запрос не ответил ни разу или нажат Ctrl+C — файла нет |
| 2 | аргументы, настройка, токен, каталог или запись файла |
| 3 | проверка содержимого или самопроверка отказала, файла нет |

**Что в файле.** Каждая запись проходит первый проход маски, строгий проход всех видов маски, в том числе выключенных по умолчанию, и режим структуры: любая строка вне белого списка становится меткой вида и длины, например `<digits:12>` или `<masked:6>`. Переключатели справочника на это не влияют. Перед записью файл проверяется своими образцами: серии от 7 цифр, e-mail, uuid, IP, даты, токены, кириллица. Одно совпадение отменяет файл. До первого запроса команда прогоняет через тот же путь встроенную синтетическую запись.

**Где файл.** `~/threadline-samples/sample-<проект>-<среда>-<время>.json`, каталог `0700`, файл `0600`. `--out` задаёт другой каталог вне репозитория, относительный путь считается от каталога запуска. Каталог внутри репозитория и символические ссылки отклоняются. Автоудаления нет: файл читают и сразу удаляют командой `--clean`. Она удаляет только файлы по шаблону имени и не читает настройку и токен.

**В контейнере.** В образе нет pnpm, поэтому команда запускается через `node`. Токен уже в окружении контейнера, файл лежит в слое контейнера и исчезает при его пересоздании:

```bash
docker compose --profile app exec -T threadline node --disable-warning=ExperimentalWarning apps/server/src/cli/sample.ts --env prod --kind all --live
docker compose --profile app exec -T threadline cat /home/node/threadline-samples/<имя из вывода>
docker compose --profile app exec -T threadline node --disable-warning=ExperimentalWarning apps/server/src/cli/sample.ts --clean
```

При файловой системе только для чтения `--out` указывает на каталог, доступный для записи.

**Команды, которые печатают токен.** `docker compose config`, `docker inspect` и `docker compose exec … env` показывают окружение контейнера вместе с токеном. Для работы с выборкой они не нужны, и их вывод нельзя пересылать.

## Вход и роли

Вход идёт через любой провайдер OIDC (например, Keycloak): Authentik, Okta, Microsoft Entra ID, Zitadel, Dex и другие с discovery по `.well-known/openid-configuration`. Раздел `auth` обязателен: без него сервер не запускается, если не заданы все три переменные входа, см. [Развёртывание: переменные](#развёртывание-переменные). Значение — настройки OIDC или `off`. Проверка раздела идёт без обращения к провайдеру.

```yaml
auth:
  issuer: https://sso.corp.example/realms/threadline   # у Keycloak адрес realm
  clientId: threadline
  publicUrl: https://threadline.corp.example   # адрес обратного вызова и выхода, без пути
  roleClaim: realm_access.roles               # Keycloak; у других провайдеров обычно groups или roles
  # scopes: [groups]                          # области сверх openid и profile, если провайдер их требует
  roles:
    business: [threadline-business]
    support: [threadline-tech-support, threadline-customer-support]
    developer: [threadline-developer]
    analyst: [threadline-analyst]
    admin: [threadline-admin]
  # caFile: ./certs/root-ca.pem               # свой корневой сертификат для провайдера, путь от этого файла
```

| Поле | Что это |
|---|---|
| `issuer` | адрес issuer провайдера, от него читается `.well-known/openid-configuration`; у Keycloak это адрес realm. `http://` только для `localhost` и `127.0.0.1` |
| `clientId` | идентификатор клиента |
| `publicUrl` | адрес самого сервиса для браузера, без пути; `http://` только для `localhost` и `127.0.0.1` |
| `roleClaim` | поле токена со списком ролей или групп: имя поля или путь через точку. Ищется сначала в токене доступа, потом в `id_token`. Поле с точкой в имени, например `https://threadline.corp.example/roles`, находится по имени целиком |
| `scopes` | необязательно: области запроса сверх `openid` и `profile`, например `groups` |
| `roles` | имена ролей или групп провайдера для каждой из пяти ролей Threadline; одно имя не может стоять у двух ролей |
| `caFile` | необязательный корневой сертификат для обращений к провайдеру |

**Где у провайдера роли.** Threadline читает из `roleClaim` список строк, одну строку или объект с ролями в ключах и сверяет с таблицей `roles`.

| Провайдер | `roleClaim` | Что настроить |
|---|---|---|
| Keycloak, роли realm | `realm_access.roles` | ничего, так по умолчанию |
| Keycloak, роли клиента | `resource_access.<клиент>.roles` | роли клиента `threadline` |
| Authentik | `groups` | группы пользователя, области по умолчанию |
| Okta | `groups` | утверждение `groups` у сервера авторизации, `scopes: [groups]` |
| Microsoft Entra ID | `roles` | роли приложения (App roles) |
| Zitadel | `urn:zitadel:iam:org:project:roles` | у проекта включена передача ролей при входе (Assert Roles on Authentication) |
| Dex | `groups` | `scopes: [groups]` |

Секреты только в окружении, в файле они запрещены: `THREADLINE_OIDC_CLIENT_SECRET` и `THREADLINE_SESSION_SECRET` (не короче 32 символов, например `openssl rand -hex 32`). В отличие от токена хранилища, без них при включённом входе сервер не запускается. Запросы к провайдеру идут через тот же `HTTPS_PROXY` и `NO_PROXY`, что и к хранилищу.

**`auth: off`** выключает вход: каждый запрос получает права администратора, в шапке постоянная метка «Вход выключен». Номера карт и секреты при этом не открываются никому. Это режим локальной работы и e2e. Сервер запустится так только с `THREADLINE_ALLOW_NO_LOGIN=1`, иначе выйдет и назовёт, что задать: забытые переменные входа не должны давать всем права администратора. На адресе, открытом в сеть, при старте выводится предупреждение. API в этом режиме отвечает только по `localhost` и IP-адресу, по доменному имени `403`: так чужая страница через перепривязку имени (DNS rebinding) не получит права администратора.

**Роли.** Бизнес, Поддержка, Разработчик, Аналитик, Администратор: каждая следующая включает права предыдущей, из нескольких действует самая сильная. Роли действуют на весь сервис. Пользователей и ролей в Threadline нет, их состав меняется только у провайдера входа, новая роль действует не позже следующего обновления сессии. Журнала входов и действий нет.

**Сессия.** Хранится в памяти сервера, в браузере только cookie `threadline.sid` (httpOnly, SameSite=Lax, Secure при `publicUrl` на https). На время входа ещё cookie `threadline.login` с путём `/api/auth` и сроком 30 минут: она связывает возврат от провайдера с браузером, который ушёл на вход, и сессии не открывает. Начатый вход сессией не считается: поток обращений к адресу входа не вытесняет сессии вошедших. Предел 12 часов от входа. После перезапуска сервера вход при живой сессии у провайдера проходит без пароля. Если провайдер не отвечает, сессии работают по последней роли до 30 минут после срока токена. Нужна одна копия сервера или липкая балансировка: задания поиска и так живут в памяти одной копии.

**Обратный прокси** сохраняет `Host` и передаёт `X-Forwarded-Proto: https`. Без этого заголовка при `publicUrl` на https cookie сессии не ставится, и вход показывает экран «настроен неверно». API отвечает только на имя из `publicUrl`, `localhost` и IP-адреса, другое имя в `Host` получает `403`. Проверки `/health/*` и `/metrics` от `Host` не зависят.

### Локальный Keycloak

Отдельный профиль `docker-compose.yml`, порт 8180 на `127.0.0.1`. Запуск отдельным именем проекта не трогает базу и том основного проекта:

```bash
docker compose -p threadline-keycloak --profile keycloak up -d keycloak
```

Команде нужен `THREADLINE_DB_PASSWORD` из `.env`, как и всему файлу compose: сама база при этом не запускается. Файл `dev/keycloak/threadline-realm.json`: realm `threadline`, клиент `threadline`, синтетический секрет `threadline-dev-client-secret` только для разработки, пять ролей, пользователи `business`, `support`, `developer`, `analyst`, `admin` и `norole`, пароль равен имени. Адреса возврата уже разрешены для портов 5173, 8080 и 8090.

Сервер запускается на машине, а не в контейнере, чтобы `issuer` был одинаков для браузера и сервера. Файл настроек:

```yaml
auth:
  issuer: http://localhost:8180/realms/threadline
  clientId: threadline
  publicUrl: http://localhost:8090
  roleClaim: realm_access.roles
  roles:
    business: [threadline-business]
    support: [threadline-tech-support, threadline-customer-support]
    developer: [threadline-developer]
    analyst: [threadline-analyst]
    admin: [threadline-admin]
```

Окружение: `THREADLINE_OIDC_CLIENT_SECRET=threadline-dev-client-secret`, `THREADLINE_SESSION_SECRET` любой не короче 32 символов, `PORT=8090`. Остановка: `docker compose -p threadline-keycloak --profile keycloak down`.

`pnpm dev` через Vite: чтобы войти через локальный Keycloak, `publicUrl` указывает на адрес Vite. По умолчанию локальная работа идёт с `auth: off`.

### Подключение провайдера OIDC

1. Администратор провайдера создаёт confidential-клиент (веб-приложение с секретом): код авторизации, PKCE S256, без входа по паролю (Direct Access Grants, Resource Owner Password). Адрес возврата: `<publicUrl>/api/auth/callback`. Адрес после выхода: `<publicUrl>/logged-out`.
2. Заводит роли или группы либо сопоставляет существующие и выбирает поле `roleClaim`, см. таблицу выше. В Keycloak роли должны быть в токене доступа, лёгкие токены выключены; роли клиента — `roleClaim: resource_access.<клиент>.roles`.
3. В `config/threadline.yaml` вместо `auth: off` пишется раздел `auth` с настоящими именами или задаются три переменные входа, в окружении задаются два секрета. Для внутреннего сертификата `caFile`, при необходимости `HTTPS_PROXY` и `NO_PROXY`.
4. Обратный прокси сохраняет `Host` и передаёт `X-Forwarded-Proto: https`.
5. Проверка: `pnpm threadline:check`, затем вход по учётной записи каждой роли.

Код при этом не меняется: другое только содержимое файла и окружения. Управление пользователями и журнал входов — у самого провайдера. Если провайдер не объявляет `end_session_endpoint`, выход удаляет сессию Threadline, а страница «Вы вышли» предупреждает, что сессия у провайдера могла остаться.

### Раздел `notifications`

Имя зарезервировано под будущие оповещения. Раздел необязателен и пока пуст: `notifications: {}`. Любое поле внутри него — ошибка «неизвестное поле». Как добавить оповещения позже, сказано в разделе «Оповещения о новых ошибках».

### Раздел `extras`

Необязательный раздел дополнений интерфейса. Без него шутки включены.

```yaml
extras:
  publicEggs: true   # по умолчанию true
```

`publicEggs: false` выключает шутки интерфейса: значения `42`, `sudo`, «кофе», чайник у шага с HTTP 418, три пустых поиска подряд, ночь, пятницу на проде, «Титры» по семи нажатиям на логотип, код Konami и 13 сентября. Браузер узнаёт значение из ответа `/api/auth/me`. Сквозные тесты ставят `false`, чтобы шутки по времени не попадали в прогон.

## Развёртывание: переменные

Значения, которые отличаются по средам, берутся из окружения запуска. Переменная важнее файла. Не задана, пуста или из пробелов: действует файл. Сам файл нужен всегда: в нём проекты, хранилища и форматы. Полный список переменных с форматом и обязательностью: [.env.example](../.env.example), развёртывание: [README.ru.md](../README.ru.md#развёртывание).

При старте сервер проверяет всё сразу и при нехватке выходит с кодом 1 одним сообщением. **Строгий запуск** `THREADLINE_STRICT_START=1` задан в образе: там обязательны ещё `THREADLINE_DATABASE_URL`, токены всех хранилищ `loki-grafana` и переменные из `tokenEnv`, `usernameEnv`, `passwordEnv` хранилищ `loki`. Вне образа он выключен: без учётных данных среды получают «не настроено», без адреса базы справочник выключен.

**По средам**

| Переменная | Заменяет | Что важно |
|---|---|---|
| `THREADLINE_GRAFANA_URL` | `url` хранилища `loki-grafana` | в `config/threadline.yaml` адреса нет: без переменной сервер и команды не запускаются и называют её. Хранилище должно быть одно: при нескольких сервер не запускается и называет их, адреса тогда задаются в файле. Если такого хранилища нет, журнал предупреждает, что переменная не применена |
| `THREADLINE_GRAFANA_PUBLIC_URL` | `publicUrl` хранилища | адрес Grafana для браузера, если сервер ходит к ней по другому адресу |
| `THREADLINE_GRAFANA_DATASOURCE` | `datasource` хранилища | имя источника Loki |
| `THREADLINE_GRAFANA_TIMEOUT_SECONDS` | `timeoutSeconds` хранилища | предел одного запроса к Grafana |
| `THREADLINE_GRAFANA_MAX_CONCURRENT` | `maxConcurrent` хранилища | сколько запросов к Grafana идёт одновременно, от 1 до 32 |
| `THREADLINE_LOKI_URL` | `url` хранилища `loki` | адрес Loki без `/loki/api/v1`. Правила те же, что у `THREADLINE_GRAFANA_URL`: хранилище `loki` одно, без адреса в файле и в переменной сервер не запускается |
| `THREADLINE_LOKI_TENANT` | `tenant` хранилища `loki` | арендатор для `X-Scope-OrgID` |
| `THREADLINE_LOKI_TIMEOUT_SECONDS` | `timeoutSeconds` хранилища `loki` | предел одного запроса к Loki |
| `THREADLINE_LOKI_MAX_CONCURRENT` | `maxConcurrent` хранилища `loki` | сколько запросов к Loki идёт одновременно, от 1 до 32 |
| `THREADLINE_PUBLIC_URL` | `auth.publicUrl` | адрес сервиса для браузера, без пути; `http://` только для `localhost` и `127.0.0.1` |
| `THREADLINE_OIDC_ISSUER` | `auth.issuer` | адрес issuer провайдера OIDC (у Keycloak адрес realm); `http://` только для `localhost` и `127.0.0.1` |
| `THREADLINE_OIDC_CLIENT_ID` | `auth.clientId` | идентификатор клиента |
| `THREADLINE_OIDC_ROLE_CLAIM` | `auth.roleClaim` | необязательна: поле ролей, например `groups`. Действует поверх раздела из файла и поверх трёх переменных входа |
| `THREADLINE_OIDC_SCOPES` | `auth.scopes` | необязательна: области запроса через пробел или запятую, например `groups` |
| `THREADLINE_CA_FILE` | `caFile`, которого нет в файле | корневой сертификат в PEM для Grafana, Loki и провайдера входа, относительный путь считается от корня проекта. `caFile` в файле важнее для своего хранилища или раздела входа. На TLS базы не влияет: там `NODE_EXTRA_CA_CERTS` |

- **Вход.** Три переменные входа задаются только вместе. Все три включают вход, даже если в файле `auth: off`. Часть из них останавливает запуск, сообщение называет недостающую. Ни одной и `auth: off` в файле: сервер не запускается без `THREADLINE_ALLOW_NO_LOGIN=1`.
- **Роли.** Без раздела в файле действуют `roleClaim: realm_access.roles` (как у Keycloak, другое поле задаёт `THREADLINE_OIDC_ROLE_CLAIM`) и имена `threadline-business`, `threadline-support`, `threadline-developer`, `threadline-analyst`, `threadline-admin`. Раздел `auth` в файле может задать только `roleClaim` и `roles`, таблица `roles` тогда заменяет встроенную целиком. У локального Keycloak другие имена поддержки, поэтому для него таблица остаётся в файле.
- **Проверки.** Те же, что у значений из файла. Сообщение называет переменную вместо поля, значения в нём нет. У сертификата называется путь: файл, который не найден, не читается или пуст, останавливает запуск.
- **Адрес для браузера.** `THREADLINE_GRAFANA_URL` не меняет `publicUrl`: если он есть в файле или в `THREADLINE_GRAFANA_PUBLIC_URL`, ссылка «Открыть в Grafana» ведёт на него, иначе на адрес из переменной.
- **Журнал.** При старте одна строка называет применённые переменные только именами: `настройки среды из окружения: THREADLINE_GRAFANA_URL, THREADLINE_CA_FILE`.

**Секреты**

| Переменная | Что это | Если не задана |
|---|---|---|
| `THREADLINE_GRAFANA_TOKEN` | токен Grafana, имя задаёт `tokenEnv` | среды хранилища получают «не настроено», при строгом запуске сервер не запускается |
| `THREADLINE_LOKI_TOKEN` или `THREADLINE_LOKI_USERNAME` и `THREADLINE_LOKI_PASSWORD` | вход в Loki напрямую, имена задают `tokenEnv`, `usernameEnv`, `passwordEnv`; Loki без входа их не требует | то же, что у токена Grafana |
| `THREADLINE_OIDC_CLIENT_SECRET` | секрет клиента OIDC | при включённом входе сервер не запускается |
| `THREADLINE_SESSION_SECRET` | ключ сессии, не короче 32 символов | при включённом входе сервер не запускается |
| `THREADLINE_DATABASE_URL` | адрес PostgreSQL с паролем | справочник и короткие ссылки выключены, проекты только из файла; при строгом запуске сервер не запускается |
| `THREADLINE_TELEGRAM_BOT_TOKEN` | токен бота для формы «Сообщить о проблеме» и оповещений о новых неописанных ошибках | форма показывает контакт поддержки, текст остаётся на экране; оповещения остаются записями журнала |
| `THREADLINE_TELEGRAM_CHAT_ID` | чат, куда бот пишет | то же |

- **Telegram.** Запросы идут к `api.telegram.org` через `HTTPS_PROXY`, если он задан; `NO_PROXY` действует. Сообщение несёт только текст человека и короткую ссылку, содержимого записей в нём нет. Номер карты или другое скрываемое значение в тексте заменяется маской перед отправкой. Предел: 5 сообщений за 10 минут на человека и 30 на сервис, описание до 2000 символов. Токен стоит в адресе запроса, поэтому текст сетевой ошибки в журнал не пишется. Прокси с подменой сертификата: корневой сертификат через `NODE_EXTRA_CA_CERTS`, `THREADLINE_CA_FILE` здесь не действует.
- **Новые неописанные ошибки.** Первая вставка ошибки в «Неизвестное» проекта всегда даёт запись журнала `warn` с `event: "unknown_error_seen"` и полями `project`, `environment`, `stand`, `system`, `method`, `code`, `status`. Если Telegram настроен, тот же бот пишет в чат: не больше 5 сообщений в минуту, остаток одной строкой, запись журнала есть на каждую ошибку. Текста ошибки, пути и запроса-примера нет ни там, ни там. Код, похожий на значение, скрыт (`code_hidden: true`). Ссылка на «Неизвестное» есть при включённом входе, адрес берётся из `auth.publicUrl` или `THREADLINE_PUBLIC_URL`. При `auth: off` ссылки нет: `THREADLINE_PUBLIC_URL` без двух других переменных входа сервер не запустит. Сбой отправки: запись `event: "unknown_error_notice_failed"`, без повторов.
- **Форма без Telegram.** Сообщение не настроено или не ушло: запись `warn` с `event: "report_not_delivered"`, `kind` и `page`. В `page` шаблон страницы без значений (`/pay/prod/requests/***`), текста человека и короткой ссылки нет.

**Обычные:** `HOST` (в образе `0.0.0.0`), `PORT` (`8080`), `LOG_LEVEL` (`info`), `THREADLINE_CONFIG`, `THREADLINE_STRICT_START` (в образе `1`), `THREADLINE_ALLOW_NO_LOGIN` (только локально), `THREADLINE_SHUTDOWN_TIMEOUT_SECONDS` (`25`), `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS`.

**Docker Compose.** Сервис `threadline`, профиль `app`. Всё из `.env` приходит через `env_file`. Переменные по средам и секреты входа можно задать ещё и в окружении запуска: они важнее `.env`. Путь `THREADLINE_CA_FILE` указывается внутри контейнера, например `config/certs/root-ca.pem` из смонтированной папки `./config`.

**Что нужно от инфраструктуры**

- PostgreSQL и пользователь с правом создавать таблицы: миграции выполняет отдельная команда, сервер схему не меняет, см. [README.ru.md](../README.ru.md#миграции).
- Ровно одна копия сервера: сессии и задания поиска живут в памяти.
- Прокси с https, который сохраняет `Host` и передаёт `X-Forwarded-Proto: https`.
- Доступ из контейнера к Grafana или Loki и к провайдеру входа. Выход к `api.telegram.org`, напрямую или через `HTTPS_PROXY`, необязателен, см. [README.ru.md](../README.ru.md#внешние-зависимости), «Внешние зависимости».
- Сервис доступен только из внутренней сети: короткие ссылки открываются без входа.

## Проекты на страницах

Если задан `THREADLINE_DATABASE_URL`, проект создаётся на странице `/admin/projects/new`, а правится в настройках проекта: `/:project/settings/main` и `/:project/settings/environments`. Правка действует сразу, без перезапуска и без перезагрузки страницы. Список проектов на `/admin/projects`, хранилища и их проверка на `/admin/status`.

**Что где лежит.** Хранилища, профили формата (`formats`), `defaults` и `search` всегда только в этом файле. Проекты, среды и логотипы при подключённой базе живут в базе, файл для них становится начальным набором. Без базы проекты читаются из файла, как раньше, страницы показывают их и объясняют, почему правка закрыта. Сервер ничего не пишет в этот файл и в его папку: она может быть смонтирована только для чтения.

**Посев и файл.** При каждом подключении к базе сервер сверяет проекты с файлом одной транзакцией. Новое из файла добавляется, проект, который не правили на странице, обновляется из файла. Проект, который правили, файлу не подчиняется: журнал, страница и `threadline:check` об этом говорят.

| Отметка на странице | Что значит | Что можно сделать |
|---|---|---|
| нет | запись совпадает с файлом или обновляется из него | |
| «Только на странице» | проекта нет в файле | |
| «Правится здесь» | проект правили на странице, файл с тех пор не менялся | «Взять из файла» |
| «Файл изменился, не применён» | файл изменился уже после правки на странице | «Взять из файла», «Оставить» |
| «Убран из файла» | проекта больше нет в файле, поэтому он скрыт | «Показать» |

Отметка видна в списке проектов и в настройках проекта, действия только в настройках. Проект, удалённый на странице и оставшийся в файле, не возвращается: журнал и страница просят убрать его из файла. Если создать проект с тем же идентификатором на странице, запрет снимается.

**Занятые идентификаторы.** `about`, `admin`, `api`, `assets`, `catalog`, `credits`, `docs`, `health`, `learn`, `metrics`, `new`, `projects`, `s` и `settings` заняты адресами страниц: проект с таким идентификатором в файле останавливает запуск, запись в базе становится неверной. Среда `settings` тоже занята: перед обновлением проверьте базу, нет ли таких записей.

**Граница формы `formScope`.** Токен Grafana читает весь Loki, поэтому форма по умолчанию не сохраняет новые условия. Администратор один раз пишет, какие значения метки форма вправе читать:

```yaml
auth: off
defaults: { project: acme, environment: prod }
backends:
  grafana:
    type: loki-grafana
    url: https://grafana.corp.example
    tokenEnv: THREADLINE_GRAFANA_TOKEN
    formScope:
      label: namespace
      values: [acme, 'acme-*']
projects:
  acme:
    name: Acme
    environments:
      prod:
        name: Прод
        backend: grafana
        selector:
          - { label: namespace, op: '=', value: acme }
```

Значение бывает точным, `начало*` или `*`. `*` снимает ограничение целиком: это явное решение, и страница хранилища это показывает. Других шаблонов нет. Условия, совпавшие с версией из файла, граница не проверяет: файл доверенный. Если границу сузить, среда из базы вне её получает «не настроено» с причиной, запись не удаляется. У имитации границы нет.

**Новая Grafana.** Адреса и токена нет ни на форме, ни в API. Новое хранилище описывается в `backends` (`type`, `url`, `tokenEnv`, при необходимости `caFile`, `formScope`), переменная с токеном задаётся в `.env` или секрете пода, сервер перезапускается. После этого хранилище появляется в списке на форме.

**Новый профиль формата.** Форма только выбирает профиль. Новый профиль описывается в `formats`, проверяется командой `pnpm threadline:check <формат> <файл>`, сервер перезапускается.

**Деплой.** ВМ: `docker compose --profile app up -d`, шаг миграций идёт перед сервером, `./config` остаётся `:ro`, в `.env` нужен адрес базы. Kubernetes: один под Threadline, потому что задания поиска живут в памяти; миграции отдельным Job; ConfigMap с файлом и логотипами, Secret с токеном и адресом базы; PostgreSQL с постоянным томом, `emptyDir` нельзя: потеря тома теперь стоит и проектов со страницы. Обратный прокси и Ingress обязаны сохранять заголовок `Host`, иначе API ответит `403`. Таймаут чтения Ingress не меньше 120 секунд, обновление `RollingUpdate`: [README.ru.md](../README.ru.md#ingress), «Ingress» и «Одна копия и остановка».

**Права.** Читают страницы проектов и запускают проверку подключения поддержка и старшие роли. Правят существующие проекты, их среды и настройку вида, скрывают и показывают проекты аналитик и администратор. Создаёт и удаляет навсегда только администратор. Журнала правок нет, откат — резервная копия.

## Короткие ссылки

Меню «Поделиться» на результатах поиска, запросе и операции: «Короткая ссылка», «Текст для тикета» и на запросе «ID запроса». «Короткая ссылка» создаёт ссылку `/s/<id>` и копирует её. Создать ссылку может любая вошедшая роль, открыть может любой без входа: сервис доступен только во внутренней сети. Запрос и операция внутри ссылки открываются на своих адресах, `/s/<id>/requests/<cid>` и `/s/<id>/operations/<type>/<value>`. Чужой идентификатор получает то же «не найдено», что неизвестная ссылка. Нужен `THREADLINE_DATABASE_URL`: без базы закрыт только пункт ссылки, с причиной, текст для тикета копируется без ссылки, вход, поиск и остальные страницы работают как обычно.

**Что открывается.** Поиск идёт заново по сохранённым условиям и текущей настройке среды, страница только для чтения. Значения всех включённых видов маски, номера карт и секреты под маской у всех, в том числе у вошедшего аналитика, глазка нет. Вид, включённый по умолчанию и выключенный в настройках проекта, на ссылке считается включённым. Виды имени, отчества, даты рождения и e-mail выключены по умолчанию: пока их не включили, эти значения видны и на ссылке, как и фамилия в свободном тексте. Технические подробности доступны всем, кто открыл ссылку, а адрес Grafana и текст ошибок хранилища в ответы не идут.

**Что хранится.** В таблице `share_link`: проект, среда или стенд, значения поиска, период точными датами, вид и цель ссылки, время создания и срок. Записей логов, результатов, автора и сведений об открытиях нет. Полный номер карты не хранится, только первые 6 и последние 4 цифры, поэтому результаты могут быть отмечены «неточное совпадение». **Телефон, личный номер и другие значения поиска лежат в базе и её резервных копиях открыто до срока ссылки:** без них поиск заново невозможен, шифрования нет. Храните копии соответственно. В адресах, журнале сервера и хранилище браузера значений нет, идентификатор ссылки в журнале заменён на `***`.

**Срок жизни.** Один месяц по умолчанию, меняет администратор на `/admin/status`, раздел настроек. Сокращение сразу действует и на созданные ссылки, продление только на новые. Отзыва отдельной ссылки и списка ссылок нет: чтобы быстро закрыть старые, поставьте на время срок 1 день. Истёкшие строки удаляются раз в час и при подключении базы; истёкшая ссылка не открывается и до этого. Удаление проекта навсегда стирает его ссылки той же транзакцией, скрытие проекта их не трогает: снова показанный проект снова открывается по прежним ссылкам.

**Нагрузка.** Задания ссылок живут отдельно от обычных и их не вытесняют: одно на ссылку, не больше трёх идущих и десяти в памяти. Четвёртая ссылка получает «Сервис занят». Несколько человек на одну ссылку дают нагрузку одного, результат держится в памяти 5 минут. Очередь хранилища (`maxConcurrent`) общая.

**Перед обновлением.** Идентификаторы проекта из списка ниже заняты адресами страниц, идентификаторы среды `catalog` и `settings` тоже. В файле такой проект не даст запустить сервер, в базе станет неверной записью: сервер запустится, страница проектов отметит запись. Проверить проекты можно так:

```sql
select id from project where id in ('about', 'admin', 'api', 'assets', 'catalog', 'credits', 'docs', 'health', 'learn', 'metrics', 'new', 'projects', 's', 'settings');
```

**Откат версии.** Прежняя версия считает применённую миграцию без файла ошибкой. Перед откатом выполните, ссылки при этом пропадают, логи и справочник не затрагиваются:

```sql
drop table share_link;
drop table service_setting;
delete from threadline_migrations where name = '0007_share_links.sql';
```

## Настройки сервиса

Раздел страницы `/admin/status`, только для администратора. Адреса `/admin/settings` и `/settings` ведут к этому разделу. У других ролей раздела нет, старый адрес показывает сообщение о недоступном разделе, API отвечает им 403, без входа 401. При `auth: off` раздел открыт всем, как и остальные права администратора.

| Настройка | Значение | По умолчанию |
|---|---|---|
| Срок жизни короткой ссылки, дней (`share.lifetimeDays`) | целое от 1 до 400 | 30 |
| Контакт поддержки, текст (`support.contactText`) | до 200 символов | пусто |
| Контакт поддержки, ссылка (`support.contactUrl`) | адрес https до 500 символов | пусто |

Настройки лежат в таблице `service_setting`, записью на настройку, и читаются из базы при каждом использовании: перезапуск не нужен, вторая копия сервера видит правку на следующем запросе. Журнала правок нет, только метка версии против одновременной правки. Запись, которая не проходит проверку, не ломает сервер: действует значение по умолчанию, страница об этом говорит, сама запись не переписывается. База не подключена: раздела нет, вместо него пояснение, действуют значения по умолчанию. База пропала: последние прочитанные значения, правка закрыта.

Новая настройка добавляется одной записью в `packages/core/src/settings.ts` и строкой текста, без миграции и нового маршрута. Секреты, адреса и настройки хранилищ остаются только в файле и окружении.

## Настройка вида проекта

Пункт «Вид» настроек проекта, адрес `/:project/settings/view`, старый `/projects/<id>?tab=view` ведёт туда же. Это выбор проекта: что показывать и как показывать. Режим «Подробно» или «Кратко» выбирает человек переключателем на страницах результатов, запроса и операции, выбор живёт в браузере. Маскирование здесь не настраивается: это общие правила в пункте «Маскирование» настроек проекта.

**Это не защита.** Настройка и режим только убирают данные с экрана. Скрытое остаётся в браузере, открывается переключателем и видно в его средствах разработчика. Данные защищает только маскирование: настройка не может открыть то, что оно скрыло.

| Часть | Что задаёт | По умолчанию | Что нельзя |
|---|---|---|---|
| Режим по умолчанию | действует, пока человек не выбрал сам | `full` | |
| Колонки: `time`, `request`, `outcome`, `component`, `duration`, `records`, `cid` | видимость в «Подробно» и в «Кратко»; статус есть всегда | в «Подробно» все, в «Кратко» `time`, `request`, `outcome`, `duration` | выключить `time`, `request`, `outcome` |
| Вкладка по умолчанию: `scheme`, `timeline`, `records` | с чего открывается запрос | `scheme` | вкладку, выключенную в обоих режимах |
| Вкладки: `scheme`, `records` | видимость в двух режимах; «Шкала времени» есть всегда | `scheme` в обоих, `records` только в «Подробно» | |
| Блоки панели шага: `request`, `response`, `headers`, `context`, `raw`, `logs` | видимость в двух режимах | в «Подробно» все, в «Кратко» `request` и `response` | выключить `raw` в «Подробно» |
| Вид тел: `pretty`, `raw` | как тела открываются в «Подробно» | `pretty` | в «Кратко» тела всегда отформатированы |

**В файле настройки вида нет.** Поле `view` у проекта в файле — ошибка «неизвестное поле», сервер не запустится и назовёт `projects.<id>.view`. Настройка живёт в строке проекта в базе, в столбцах `view_settings` и `view_updated_at`, и правится отдельно от проекта, со своей меткой версии: сохранение вида не делает проект «правленым на странице», не останавливает поиски и не конфликтует с открытой формой проекта.

**Без базы** действуют встроенные значения, пункт «Вид» только показывает их, а переключатель режима работает. База пропала: действует последний снимок, правка закрыта. Устаревшая запись не ломает проект: неизвестное отбрасывается, недостающее берётся из встроенных значений, пункт «Вид» называет отброшенное, а запись меняется только при сохранении.

**Резервная копия.** Настройка вида есть только в базе, поэтому переноса файлом нет: при потере тома проекты посеются заново из файла с встроенными значениями. Берегите её той же копией `pg_dump`, что и справочник (раздел «Резервная копия»).

## Справочник

Справочник методов, систем и ошибок даёт названия в результатах поиска и решает итог ответа по правилам.
Он живёт в PostgreSQL в отдельном контейнере рядом с Threadline, а не в этом файле и не в общем
кластере баз. Без базы Threadline работает как раньше: пути читаемые, названий нет.

### Переменные

| Переменная | Что значит |
|---|---|
| `THREADLINE_DATABASE_URL` | адрес базы: `postgres://threadline:<пароль>@127.0.0.1:5432/threadline`. Не задан — справочник выключен. В YAML адреса нет |
| `THREADLINE_DB_PASSWORD` | пароль контейнера базы для `docker compose`. Совпадает с паролем в адресе. Генерируйте так: `openssl rand -hex 24`. Другие символы: `/ ? # @ : %` и пробел в адресе кодируются (`encodeURIComponent`); `#` и `$` не используйте: сервер и `docker compose` читают такую строку `.env` по-разному, и пароли в базе и у сервера разойдутся. Пароль фиксируется при первом создании тома: после смены `THREADLINE_DB_PASSWORD` том нужно пересоздать, иначе справочник не подключится |
| `THREADLINE_DB_PORT` | порт базы на этой машине, по умолчанию `5432` |

TLS и свой корневой сертификат задаются параметрами адреса (`?sslmode=verify-full`) и `NODE_EXTRA_CA_CERTS`.
Пароль не печатается ни в журнале, ни в состоянии справочника: там только `хост:порт/база`.

### База

- **Разработка:** `docker compose up -d db`, затем `pnpm threadline:migrate`. В `.env` — пароль и адрес с хостом `127.0.0.1`, пример в `.env.example`.
- **ВМ:** `docker compose --profile app up -d` поднимает базу, выполняет миграции и запускает Threadline. В `.env` адрес с хостом `db`. Порт базы открыт
  только на `127.0.0.1`. Профиль `app` не даёт случайно поднять второй Threadline на занятом порту 8080.
- **Под Kubernetes:** тот же образ Postgres отдельным контейнером на один экземпляр с постоянным томом, адрес —
  `THREADLINE_DATABASE_URL` из секрета пода.

**Осторожно:** `docker compose --profile app config` печатает значения из `.env`, в том числе токен Grafana.

Схему ставит отдельная команда: `pnpm threadline:migrate`, в образе `node --disable-warning=ExperimentalWarning apps/server/src/cli/migrate.ts`. SQL-миграции из
`apps/server/src/catalog/migrations`, учёт в таблице `threadline_migrations`, второй запуск ждёт первый. Миграции только вперёд. Сервер схему не меняет: если
она отстала до первой загрузки справочника, справочник в состоянии `error`, журнал называет команду, `/health/readiness` отвечает 503, а после команды сервер сам становится готов. Если схема отстала у работающего сервера, готовность остаётся 200 с `stale`, правка закрыта до команды.

### Состояния

`GET /api/catalog` отдаёт состояние справочника:

| Состояние | Когда | Что видит пользователь |
|---|---|---|
| `off` | `THREADLINE_DATABASE_URL` не задан | названий нет, полосы нет |
| `connecting` | база недоступна, данных ещё не было; повторы с паузой от 1 до 30 с | «Справочник недоступен: названия не показаны» |
| `ok` | справочник загружен | названия, правка в редакторе |
| `stale` | база пропала после загрузки | последние данные с временем загрузки, правка закрыта |
| `error` | схема отстала: журнал называет команду миграций, сервер проверяет снова и сам продолжает после команды. Изменённая или лишняя миграция, адрес не разобран (неверная схема, не закодированные символы пароля): повтора нет, нужно исправить настройку и перезапустить сервер | как `connecting`, в редакторе — текст ошибки |

Сервер не ждёт базу при старте: порт открывается сразу, подключение идёт в фоне. Правка другой копии сервера видна
через опрос версии раз в 30 с.

### Маскирование

Всё, что сервер скрывает, это 13 видов маски одного списка: номер карты, секреты, данные карты, токен карты, номер счёта, телефон, личный номер, паспорт, фамилия, имя и отчество, дата рождения, e-mail, адрес. Настройка одна на проект, все среды: пункт «Маскирование» настроек проекта (`/:project/settings/masks`) или раздел `masking` файла проекта.

- **Состояние.** Имя и отчество, дата рождения и e-mail выключены по умолчанию и, пока их не включили, ничего не меняют. Остальные включены. Выключенный вид, включённый по умолчанию, открыт только в блоках подробностей записи.
- **Без выключателя.** Номер карты и секреты не выключаются ни в редакторе, ни файлом, ни запросом в обход формы. Встроенные поля этих видов распознаются всегда, без базы. Добавленные к ним поля работают, только пока база доступна.
- **Кто открывает.** Одна таблица в коде, `packages/core/src/search/mask-kinds.ts`: номер карты глазком открывают поддержка, разработчик, аналитик и администратор; секреты глазком открывают аналитик и администратор; остальные виды глазком открывают поддержка и разработчик, а аналитику и администратору они открыты сразу в блоках подробностей. Бизнес и короткие ссылки не открывают ничего. Смена решения о виде меняет одну строку этой таблицы.
- **Без входа и при `auth: off`.** Глазок открывает все виды с выключателем, номер карты и секреты остаются под маской. Выключить вид и показать значения может каждый, кто открыл страницу; журнала показов нет.
- **Глазок один на страницу запроса.** `GET …/requests/:cid/reveal`, ответ `no-store`. Из живого задания чтения хранилища нет, задание истекло или открыта ссылка: одно чтение окна запроса на нажатие. Пока значение открыто, «Копировать» у блока даёт открытое значение. Значение, которое приложение скрыло до записи в лог, показ не вернёт. Токены хранилищ, секреты входа и пароль базы не показываются никому.
- **Настройка при недоступной базе.** Справочник выключен: состояния по умолчанию. База недоступна и данных нет: включены все виды, настройка неизвестна. База пропала после загрузки: действует последняя настройка.

### Начальный набор и файл справочника

`config/catalog/<проект>.yaml` — начальный набор проекта. Сервер импортирует его при подключении к базе, если файл
изменился, и не трогает записи, которые правили в редакторе. Формат, схема и примеры — в
[catalog/README.md](catalog/README.md), схема JSON — `catalog/catalog.schema.json`.
В сервисе тот же файл открывается страницей «Файл проекта» (`/:project/settings/file`): текст проекта с настройками, маскированием и справочником, проверка на лету, применение кнопкой. Через API применение требует `baseVersion`: версию дают выгрузка и проверка.

```bash
pnpm threadline:catalog export pay pay-now.yaml         # выгрузка
pnpm threadline:catalog import pay my.yaml --dry-run    # проверка без записи: что добавится, изменится, скроется
pnpm threadline:catalog import pay my.yaml [--force]    # загрузка; --force заменяет и ручные правки
pnpm threadline:catalog schema catalog.schema.json      # схема JSON файла
```

Коды выхода: 0 — успех, 1 — ошибки файла или аргументов, 2 — база недоступна или адрес не задан.

То же в сервисе: страница «Файл проекта», на неё ведёт кнопка «Файл» в справочнике. Пока база недоступна, применение закрыто.

В репозитории лежит набор демо-проекта `config/catalog/pay.yaml`: выдуманные системы выдуманного платёжного шлюза Demo Pay,
адреса — домены `*.example` и адреса для документации (RFC 5737). Набор своего проекта пишут руками или генерируют по схеме
и кладут рядом под именем `<проект>.yaml`.

### Удаление записей

Удаление записи всегда обратимо: запись скрывается, перестаёт участвовать в сопоставлении и видна в фильтре «Скрытые», откуда её можно вернуть. Вместе с системой или методом из сопоставления уходят их зависимые записи, а при возврате они возвращаются. Зависимая запись, скрытая отдельно, остаётся скрытой.

Удалить навсегда может только администратор и только запись, которую уже удалили мягко. Зависимые записи стираются той же транзакцией. Для записей из файла остаётся отметка в таблице `catalog_deleted`, поэтому новый файл их не добавит. Запись, созданная в редакторе и никогда не бывшая в файле, отметки не даёт.

Импорт файла и посев не возвращают и не уничтожают удалённое молча:

| Случай | Без `--force` | С `--force` |
|---|---|---|
| Запись удалил человек, файл её не скрывает | группа «Удалённые записи файл не возвращает», остаётся скрытой | группа «Будет возвращено» |
| Запись скрыта файлом, новый файл её не скрывает | группа «Будет возвращено» | группа «Будет возвращено» |
| Запись удалена навсегда, файл её несёт | группа «Удалённые записи файл не возвращает» | добавляется, отметка снимается |
| Запись скрыта, файл тоже её скрывает | без изменений | без изменений |
| Записи нет в файле | «нет в файле», остаётся | то же |

Посев всегда идёт без `--force`, журнал называет число таких записей. Новое создание записи с тем же ключом в редакторе снимает отметку.

**Откат на версию без мягкого удаления.** Прежняя версия считает применённую миграцию без файла ошибкой и переводит справочник в состояние `error`. Перед откатом в базе выполняются:

```sql
drop table catalog_deleted;
delete from threadline_migrations where name = '0006_catalog_deleted.sql';
```

Записи, скрытые мягким удалением, в прежней версии видны в фильтре «Скрытые» и работают как обычно.

### Оповещения о новых ошибках

Оповещений о новых ошибках в этой версии нет: ни настроек чатов, ни очереди, ни повторов. Бот Telegram есть только у формы «Сообщить о проблеме», см. [Развёртывание: переменные](#развёртывание-переменные). Заготовка одна: когда неизвестная ошибка впервые записана в «Неизвестное» проекта, `UnknownCollector.flush` один раз зовёт `UnknownErrorNotifier.unknownError` из `apps/server/src/catalog/notifier.ts` с данными строки. Текст в них уже с маской. По умолчанию стоит `NO_NOTIFIER`, который ничего не делает. Сбой уведомления не мешает записи, в журнал идёт только тип ошибки.

Чтобы добавить оповещения позже: реализовать этот интерфейс, описать поля в разделе `notifications` файла настроек (сейчас он пуст, любое поле внутри него ошибка) и передать объект в `buildApp` параметром `unknownNotifier`. Новых зависимостей и внешних запросов заготовка не несёт.

### Резервная копия

`pg_dump` той же версии, что и база, поэтому — внутри контейнера:

```bash
mkdir -p backup
# копия
docker compose exec -T db pg_dump -U threadline -d threadline -Fc > backup/threadline-$(date +%F).dump
# восстановление: остановить Threadline, затем
docker compose exec -T db pg_restore -U threadline -d threadline --clean --if-exists --no-owner < backup/threadline-2026-11-02.dump
```

- Копия содержит справочник, «Неизвестное», проекты со страниц с логотипами и настройкой вида, короткие ссылки со значениями поиска до их срока (см. [Короткие ссылки](#короткие-ссылки)), настройки сервиса и таблицу миграций. После восстановления сервер стартует без новых миграций. Адресов хранилищ и токенов в копии нет, только идентификаторы хранилищ.
- `pnpm threadline:catalog export pay backup/pay.yaml` — читаемая копия справочника для ревью. Она не заменяет дамп: в ней нет
  «Неизвестного» и отметок ручных правок.
- Расписание — на усмотрение администратора. Пример строки crontab: копия каждую ночь, хранение 14 дней:

  ```
  30 2 * * * cd /opt/threadline && docker compose exec -T db pg_dump -U threadline -d threadline -Fc > backup/threadline-$(date +\%F).dump && find backup -name 'threadline-*.dump' -mtime +14 -delete
  ```

- **Осторожно:** `docker compose down -v` удаляет том `threadline-db` вместе со справочником и проектами со страниц. После этого сервер засеет проекты из файла, а созданные только на странице пропадут. Без `-v` данные остаются.

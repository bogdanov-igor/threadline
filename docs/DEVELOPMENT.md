# Threadline: разработка

Развёртывание описано в [README.ru.md](../README.ru.md). Здесь то, что нужно для работы над кодом и настройкой на своей машине.

Сервис для просмотра логов проектов. По идентификатору находит записи, сшивает их в запросы и показывает каждый запрос шагами через системы. В репозитории один проект — демо-проект Demo Pay, выдуманный платёжный шлюз на синтетических записях. Логи читаются из Loki: через Grafana или напрямую.

В этой версии готовы:
- проекты и среды, подключение к Grafana с проверкой, оболочка интерфейса, темы;
- поиск запросов по значению (user_id, номер карты или его маска, correlation_id, id операции, любой текст) за период до 24 часов: список запросов со статусом и причиной ошибки, вкладка «Все записи»;
- страница запроса: граф потока на вкладке «Схема», шкала времени и записи с телами, ссылка на запрос;
- операция: кнопка «Открыть операцию» находит потоки одной асинхронной операции по её id, страница операции со своей ссылкой показывает итог, ход статусов и список потоков;
- справочник методов, систем и ошибок в PostgreSQL: названия в списке запросов и на странице запроса, итог ответа по правилам, редактор на странице `/:project/catalog` с разделом «Неизвестное», файл проекта на странице `/:project/settings/file`, командой и через API ([«Справочник»](#справочник)). Без базы сервис работает с читаемыми путями и без названий;
- маскирование в ответах сервера: один список из 13 видов маски (номер карты, секреты, данные карты, токен карты, номер счёта, телефон, личный номер, паспорт, фамилия, имя и отчество, дата рождения, e-mail, адрес), глазок на странице запроса, таблица «кто открывает» и настройка на странице `/:project/settings/masks`;
- профили формата записей: разбор строк и выражение подсчёта correlation_id задаются для каждого проекта ([config/README.md](../config/README.md), «Формат записей»).

## Быстрый старт

Нужны Node 24 и pnpm.

```bash
nvm use                      # Node 24 из .nvmrc
pnpm install
cp .env.example .env         # адрес Grafana там образец, для настоящего Loki впишите THREADLINE_GRAFANA_URL и THREADLINE_GRAFANA_TOKEN
                             # для работы без входа допишите в .env: THREADLINE_ALLOW_NO_LOGIN=1
docker compose up -d db      # база, если нужен справочник; пароль и адрес в .env, пример в .env.example
pnpm threadline:migrate        # схема базы: отдельный шаг, сервер её не меняет
```

Настоящего адреса Grafana в `config/threadline.yaml` нет: без `THREADLINE_GRAFANA_URL` сервер и команды не запускаются и называют переменную. В файле стоит `auth: off`, поэтому сервер требует настроить вход или задать `THREADLINE_ALLOW_NO_LOGIN=1`; демо-среде нужно то же. Источник Loki по умолчанию ищется по имени `Loki`.

```bash
pnpm threadline:check --env prod # проверить подключение, тела записей не читаются
pnpm build && pnpm start        # http://127.0.0.1:8080
```

Без токена и базы сервер тоже запускается: прод показывает состояние «не настроено», демо-среда работает на синтетических записях. В образе иначе: там задан `THREADLINE_STRICT_START=1`.

Те же синтетические записи в настоящий Loki пишет генератор быстрого старта: `pnpm threadline:demo-logs --url http://localhost:3100`, сначала записи за сутки, затем новый запрос каждые 10 секунд (`--interval`, `--no-history`). Код в `apps/server/src/demo-logs`, запуск в compose: [README.ru.md](../README.ru.md#быстрый-старт), «Быстрый старт».

## Проверочная команда

У `pnpm threadline:check` два режима: проверка подключения к среде и проверка профиля формата на образце строк.

### Проверка подключения

`pnpm threadline:check --env <среда> [--project <проект>]` делает с настоящим токеном три вещи:
- проверяет подключение;
- выводит имена индексных меток Loki;
- выводит список живых стендов PR.

Тела записей команда не читает и не печатает. Код выхода 0, если подключение есть.

```
Среда: Demo Pay / Prod (хранилище grafana, loki-grafana)
Подключение: подключено
Индексные метки за 5 минут (12): app_kubernetes_io_component, cluster, container, namespace, ...
Живые стенды за 7 дней (2): 105, 92
```

Если подключения нет, команда называет причину и что сделать: токен недействителен, нет прав, источник не найден, сеть, сертификат, тайм-аут, перегрузка.

### Проверка формата на образце

`pnpm threadline:check <формат> <файл> [--label container=app ...]` разбирает строки файла профилем формата (встроенный `json` или имя профиля из `formats`). Одна строка файла — одна строка хранилища, `--label` задаёт метки строк. Команда печатает число строк по вариантам и видам, долю строк с correlation_id, номера строк, где ключ подсчёта не совпал с разобранным, и поля профиля, которые не дали значения ни на одной строке. Значений и тел из образца команда не печатает. Подробнее — [config/README.md](../config/README.md), «Формат записей», «Проверка на образце».

## Выборка живых записей

`pnpm threadline:sample` читает немного настоящих записей и пишет вне репозитория файл только с устройством записей: ключи, виды и длины значений, шаблоны путей, разрешённые метки и коды. Значений клиентов в файле нет, в терминал идут только путь и числа.

```bash
pnpm threadline:sample --env demo --kind all --since 24h # проверка без сети и токена: демо-среда, файл с source: mock
pnpm threadline:sample --env prod --kind all --live      # настоящая выборка, нужны доступ к Grafana и токен
pnpm threadline:sample --clean                           # удалить файлы выборки
```

Среда и вид указываются всегда, значений по умолчанию нет. Настоящее хранилище читается только с `--live`. Виды: `labels` (метки шлюза), `background` (фоновый запуск), `names` (названия и правила итога), `all`. Команда запускается только руками, сервер и интерфейс её не используют. Подробности — [config/README.md](../config/README.md), «Выборка живых записей».

## Разработка

```bash
pnpm dev        # интерфейс http://localhost:5173 с прокси /api на сервер :8080
pnpm test       # модульные тесты; тесты справочника на сервере берут PostgreSQL из Docker (контейнер threadline-test-pg, порт 55432)
pnpm test:e2e   # сквозные тесты Playwright; один раз: pnpm --filter @threadline/web exec playwright install chromium
pnpm test:e2e:pg # те же сквозные тесты на PostgreSQL из docker-compose.yml (проект compose threadline-e2e, порт 55433)
pnpm lint
pnpm typecheck
```

Справочник в сквозных тестах: основной сервер по умолчанию берёт PGlite в памяти (`pglite://memory`), `pnpm test:e2e:pg`
поднимает настоящий PostgreSQL в отдельном проекте compose со своим томом, выполняет миграции и удаляет том после прогона. С
`THREADLINE_E2E_DATABASE_URL=off` справочник выключен: наборы со справочником пропускаются, остальные проверяют интерфейс без
названий. `THREADLINE_DATABASE_URL` разработчика в сквозные тесты не попадает.

Серверные тесты справочника пропускаются только без Docker: предупреждение стоит в начале вывода и ещё раз после итога, код
выхода нулевой. При любой другой причине эти файлы падают и код выхода ненулевой: порт 55432 занят, на нём другой пароль,
`THREADLINE_TEST_DATABASE_URL` не отвечает. Свою базу задаёт `THREADLINE_TEST_DATABASE_URL`, нужен пользователь с правом создавать базы.

Сквозные тесты собирают интерфейс в `apps/web/dist-e2e` и запускают серверы с `THREADLINE_ALLOW_NO_LOGIN=1`, пустыми `THREADLINE_GRAFANA_URL` и `THREADLINE_GRAFANA_TOKEN`: `apps/web/dist`,
который отдаёт запущенный Threadline, и живая Grafana не затрагиваются.

Сервер запускается прямо из TypeScript встроенными средствами Node 24, отдельной сборки нет. Интерфейс собирает Vite.

### Знак, значки и установка как приложение

Знак «Маршрут» описан один раз в `apps/web/src/components/shell/mark.ts`: по нему рисуется знак в шапке и все значки. Значки
в `apps/web/public/` (`favicon.svg`, `favicon-32.png`, `apple-touch-icon.png`, `icons/icon-192.png`, `icons/icon-512.png`,
`icons/icon-maskable-512.png`) делает `pnpm --filter @threadline/web icons` из знака и токенов тем в `src/styles/index.css`, без
внешних сервисов; готовые файлы хранятся в git. Модульный тест сверяет `favicon.svg` со знаком и цветами и размеры PNG.

Манифест и воркер приложения добавляет `vite-plugin-pwa` (`vite.config.ts`) только в сборку, регистрирует воркер
`src/lib/pwa.ts`, тоже только в сборке: при `pnpm dev` воркера нет. Воркер держит в кэше только оболочку (разметку, код, стили,
шрифты, значки). Переход на страницу всегда идёт на сервер, разметка из кэша нужна только без сети. `/api/*`, `/health*` и
`/metrics` воркер не обслуживает. Новая версия воркера ждёт и включается на следующей загрузке страницы. Сквозные тесты запрещают
воркер всем наборам, кроме `e2e/pwa.spec.ts`.

## Переменные окружения

Читаются из окружения процесса и из `.env` в корне. Уже заданные в окружении значения `.env` не перезаписывает. Полный список с форматом и обязательностью: [.env.example](../.env.example). Формат `config/threadline.yaml` описан в [config/README.md](../config/README.md).

### Сертификат Grafana

Если сертификат Grafana подписан внутренним центром сертификации, положите корневой сертификат в PEM рядом с настройкой и укажите путь в `backends.grafana.caFile` или в переменной `THREADLINE_CA_FILE`. Отключить проверку сертификата нельзя.

### Открыть Threadline в сеть

Вход через OIDC (например, Keycloak) и пять ролей настраиваются разделом `auth` (`config/README.md`, раздел «Вход и роли»). В `config/threadline.yaml` пока стоит `auth: off`: без `THREADLINE_ALLOW_NO_LOGIN=1` сервер не запускается. С ней вход выключен, кто видит адрес, тот работает с правами администратора, в шапке видна метка «Вход выключен». Поэтому по умолчанию сервер слушает только `127.0.0.1`. Чтобы открыть его в сеть, задайте `HOST=0.0.0.0`. При старте сервер напечатает предупреждение. API отвечает только по `localhost` и IP-адресу: по доменному имени машины он ответит `403`, так чужая страница не доберётся до него через перепривязку имени.

## Docker

Образ, его переменные и запуск описаны в [README.ru.md](../README.ru.md#развёртывание). Команда `docker compose --profile app up -d` на ВМ поднимает базу, выполняет миграции и запускает Threadline.

Учётные записи локального Keycloak (`dev/keycloak/threadline-realm.json`) и пароль по умолчанию в `docker-compose.yml` нужны только для разработки, в образ они не попадают.

## Справочник

Справочник методов, систем и ошибок хранится в PostgreSQL в отдельном контейнере рядом с Threadline (`docker-compose.yml`):

```bash
docker compose up -d db                            # база для разработки; пароль и адрес — в .env, пример в .env.example
pnpm threadline:migrate                              # схема базы: после первого запуска и после обновления
docker compose --profile app up -d                 # на ВМ: база, миграции и Threadline
pnpm threadline:catalog import pay my.yaml --dry-run # файл справочника: проверка без записи
pnpm threadline:catalog export pay pay-now.yaml     # выгрузка
```

Файл можно загрузить и выгрузить и в сервисе: страница «Файл проекта» `/:project/settings/file`, на неё ведёт кнопка «Файл» в справочнике.

Без `THREADLINE_DATABASE_URL` справочник выключен. Если база недоступна, Threadline продолжает работать без названий.
Переменные, состояния, начальный набор и резервная копия (`pg_dump`, `pg_restore`) — в [config/README.md](../config/README.md#справочник),
формат файла — в [config/catalog/README.md](../config/catalog/README.md).

## Проекты

Страница `/admin/projects` показывает проекты и среды, хранилища и их проверка на `/admin/status`. При подключённой базе проект создаётся на `/admin/projects/new` и правится в настройках проекта, правка действует сразу. Файл `config/threadline.yaml` остаётся начальным набором, а хранилища, токены и профили формата задаются только в файле. При `auth: off` править проекты может любой, кто открыл Threadline. Подробности — в [config/README.md](../config/README.md#проекты-на-страницах).

## Короткие ссылки и настройки сервиса

Меню «Поделиться» на результатах поиска, запросе и операции даёт короткую ссылку `/s/<id>`, текст для тикета и на запросе ID запроса. Открыть ссылку может любой без входа во внутренней сети: поиск идёт заново по сохранённым условиям, страница только для чтения, значения под маской. Запрос и операция внутри ссылки открываются на своих адресах, `/s/<id>/requests/<cid>` и `/s/<id>/operations/<type>/<value>`. Нужен `THREADLINE_DATABASE_URL`. Значения поиска лежат в базе и её копиях до срока ссылки, полный номер карты не хранится. Срок жизни, месяц по умолчанию, меняет администратор на странице `/admin/status`, раздел настроек. Подробности и команды отката — в [config/README.md](../config/README.md#короткие-ссылки).

## Режимы и вид

На страницах результатов, запроса и операции есть переключатель «Подробно» и «Кратко». «Кратко» для бизнеса: хосты, IP, коды, адреса, идентификаторы, заголовки и сырые записи убраны с экрана, последовательность шагов, имена, статусы, итог и причина остаются. Без записи справочника система называется коротким именем хоста или словами «Внешняя система», метод — шаблоном пути.

**Это не защита.** «Кратко» только убирает подробности с экрана: скрытое остаётся в браузере и открывается одним нажатием. Данные защищает только маскирование.

Выбор запоминается в браузере отдельно для каждого проекта и не входит в ссылку: коллега открывает запрос в своём режиме, как и с показом скрытого. Смена режима не отправляет запросов ни к серверу, ни к Grafana.

Что показывать по умолчанию, какие колонки, вкладки и блоки есть в каждом режиме и как открываются тела, решает проект в пункте «Вид» настроек, `/:project/settings/view`. Настройка живёт в базе, а не в файле: состав и встроенные значения описаны в [config/README.md](../config/README.md#настройка-вида-проекта).

## Устройство

```
apps/server     Fastify: API, проверка подключения, задания поиска и поиска операции, база и API справочника, раздача собранного интерфейса
apps/web        React 19, Vite, Tailwind CSS 4, shadcn/ui, граф потока на React Flow
packages/core   общие типы и API, схема настройки, время; поиск: значения, статус и причины, записи и трасса запроса, маскирование; профили формата записей; справочник: сопоставление и правила итога; модель графа потока и операции
config/         настройка проектов, сред и хранилищ; config/catalog: начальный набор и схема файла справочника
deploy/         быстрый старт в Docker: Threadline, Loki, Grafana и демо-логи
dev/            снимки документации, Keycloak для разработки
```

Ссылка «Открыть в Grafana» в результатах поиска и на странице запроса открывает Explore в новой вкладке, в браузере пользователя и под его учётной записью. Threadline строит адрес без обращения к Grafana и ничего не отправляет. Настройка и то, какие значения попадают в адрес, описаны в `config/README.md`.

Сервер обращается к Loki только через прокси источника Grafana (`/api/datasources/proxy/{id}/...`, в Grafana 13 `/api/datasources/proxy/uid/{uid}/...`), и каждый запрос ограничен селектором среды. Одинаковые одновременные запросы уходят в Grafana один раз. Число параллельных запросов ограничено: если очередь не освободилась, пользователь видит «Threadline занят».

Поиск идёт на сервере заданием: первый проход считает записи по correlation_id кусками по часу, второй забирает записи найденных запросов пакетами. Интерфейс опрашивает состояние задания, в том числе со скрытой вкладки. Без опроса дольше 90 секунд (вкладку закрыли) сервер останавливает задание и прерывает его запросы к хранилищу; кнопка «Стоп» и новый поиск останавливают прежний сразу. Результат хранится в памяти сервера 15 минут с последнего обращения. Поиск операции идёт таким же заданием: его запускает кнопка на странице запроса или открытие адреса операции без живого задания (ссылка, закладка, обновление страницы после истечения). У него те же пределы. Проверка подключения, «Все записи» и страница запроса по ссылке — обычные запросы: ушедший пользователь их обрывает. Других фоновых запросов, в том числе периодического опроса Grafana, нет. Граф потока и справочник работают с уже прочитанными записями и запросов к Loki не добавляют.

Как превратить документацию и сваггеры в справочник: [config/catalog/PLAYBOOK.md](../config/catalog/PLAYBOOK.md).

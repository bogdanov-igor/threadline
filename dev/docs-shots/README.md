# Снимки экрана и схемы для документации

## Страницы

Файл `apps/web/src/features/docs/content/ru/docs/<страница>.md` открывается по адресу `/docs/<страница>`, файл `content/ru/learn/<страница>.md` по адресу `/learn/<страница>`.

- Первая строка файла: `# Название`. Оно же название в меню и в «Назад», «Дальше». Заголовок первого уровня в файле один.
- Разделы страницы: `##`, подразделы: `###`. Из `##` собирается список «На странице», когда их три и больше.
- Группа в меню определяется началом имени: `guide-`, `file-`, `arch-`, `admin-`. Файл с таким началом сразу виден в меню.
- Порядок страниц задаёт `apps/web/src/features/docs/menu.ts`. Страница, которой нет в списке, стоит в конце своей группы.
- Таблицы и блоки кода работают. Сырой HTML не показывается.
- Врезка «важно»: строка, которая начинается с `> `.
- Ссылка на другую страницу: `[Поиск](/docs/guide-search)`, только в конце страницы.

## Картинка в тексте

На отдельной строке:

```md
![Подпись под картинкой](shot:guide-search-form)
![Подпись под схемой](diagram:arch-overview)
```

Подпись видна под картинкой и читается экранным диктором. Если снимка или схемы ещё нет, на странице виден заметный пробел с именем: страница не падает.

## Снимки

Снимки делает один скрипт. Он собирает интерфейс, запускает сервер на имитации хранилища и базе в памяти, проходит списки и пишет PNG в `apps/web/src/features/docs/content/shots/<язык>/`, по умолчанию `ru`. Страница на другом языке берёт снимок своего языка, а если его нет, русский. Живая Grafana и рабочий Threadline не затрагиваются, данные только синтетические, тема светлая. Два прогона снимков не идут одновременно: скрипт ждёт каталог `THREADLINE_DOCS_SHOTS_LOCK`, по умолчанию `threadline-docs-shots.lock` во временной папке.

```bash
source ~/.nvm/nvm.sh >/dev/null && nvm use 24 >/dev/null
pnpm docs:shots                     # все списки
pnpm docs:shots guide               # только dev/docs-shots/guide.list.mjs
pnpm docs:shots guide --only a,b    # только снимки с такими именами
pnpm docs:shots guide --no-build    # без сборки: интерфейс тот же, что в прошлый раз
pnpm docs:shots guide --out /tmp/x  # проба: файлы в другую папку, документация не меняется
pnpm docs:shots --lang en           # английский интерфейс, снимки в shots/en
DOCS_SHOTS_PORT=8590 pnpm docs:shots # порты подряд с 8590 вместо случайных свободных
```

Список это файл `dev/docs-shots/<группа>.list.mjs`:

```js
import { openRequest, search } from './helpers.mjs';

export default [
  {
    name: 'guide-search-results',            // имя файла, оно же имя в shot:<имя>. Латиница, цифры, дефис. Начинайте с имени своей группы.
    path: '/pay/prod',                        // какой адрес открыть
    viewport: { width: 1280, height: 720 },  // необязательно, по умолчанию 1280 на 800
    async actions(page) {                    // необязательно: что сделать до снимка, page из Playwright
      await search(page, ['getCard']);
    },
    crop: (page) => page.getByTestId('search-results'),  // необязательно: снять только этот элемент
    pad: 8,                                  // необязательно: сколько пикселей страницы оставить вокруг элемента
    fullPage: true,                          // необязательно, без crop: страница целиком, а не только окно
    role: 'support',                         // необязательно: войти этой ролью (business, support, developer, analyst, admin). Без неё вход выключен
  },
];
```

Советы:

- Колонка текста шириной 760px. Снимок окна 1280 в ней уменьшается почти вдвое, мелкий текст читается плохо. Чаще снимайте часть страницы через `crop`.
- Что есть в данных: среды `/pay/prod`, `/pay/test`, `/pay/demo`, стенды `/pay/pr/<номер>`, проект один — демо-проект Demo Pay. Значения для поиска и готовые сценарии лежат в `apps/server/src/backends/mock/dataset-pay.ts`.
- `pnpm docs:shots` снимает всё заново на одном сервере, база в памяти общая на прогон. Если снимок что-то меняет в данных, это видят следующие снимки того же прогона.
- Сбой одного снимка не мешает остальным: старый файл остаётся, в конце виден список сбоев и код выхода 1.
- Списки пишутся по русскому интерфейсу. С `--lang en` строки интерфейса в `getByRole`, `getByText`, `getByLabel` и `filter` переводятся по файлам строк (`translate.mjs`). Данные демо-проекта (справочник, среды, записи) уже на английском и одинаковы на обоих языках. Словарь `data.en.json` переводит только остальное русское в данных снимка: имена пользователей ложного сервиса входа и примеры русских страниц, которые список вводит в поля или в файл проекта. Через него проходят ответы API и ввод. Новый русский текст в данных снимка добавьте в словарь, иначе на английском снимке он останется русским. Строка, которой нет ни в файлах строк, ни в словаре, не переводится: для неё нужен `data-testid`.
- Образец: `dev/docs-shots/example.list.mjs`. Он пишется только во временную папку: `pnpm docs:shots example`, путь виден в конце вывода.

## Схемы

Схема это небольшой компонент React в `apps/web/src/features/docs/diagrams/`: прямоугольники, стрелки, простые слова. Цвета только из переменных темы, поэтому схема работает в тёмной теме. Подписи лежат в `diagrams/strings/ru.json`, чтобы их потом перевести.

Новая схема:

1. Скопируйте `diagrams/ArchOverview.tsx`, части берите из `diagrams/parts.tsx`.
2. Добавьте подписи в `diagrams/strings/ru.json`.
3. Добавьте строку в `diagrams/index.ts`: имя и компонент.
4. В тексте: `![Подпись](diagram:<имя>)`.
